# 여행 준비에서 생성된 공동 캔버스까지

기존 밝은 Wayfind 화면의 헤더·왼쪽 메뉴·참여자 목록·초대 코드 복사 알림·연두색 실행 버튼을 유지한다. 지역 사진 카드 높이는 변경하지 않는다. 기본조건에서 별도 출발 위치 상세·숙소·고정 약속 입력을 제거하고, 출발 장소와 첫날 출발 시각을 기존 조건 API에 저장한다. 장소는 같은 입력에서 검색할 수 있으며 좌표를 확인하지 못하면 이동 시간은 미확인이다.

내 취향의 최초 AI 분석에서 실제 예약한 숙소와 약속도 scheduleItems로 정리한다. 항목이 있을 때만 기존 취향 아래에 표시하며 장소·날짜·시각·공유 범위를 그 자리에서 수정한다. 정보가 부족하면 해당 필드만 안내한다. 개인 일정은 본인 입력에 보관하고 공통 코스에 고정하지 않는다. 방장이 명시적으로 지정한 공통 일정만 전체 경로 기준점이다. 원문·해석 근거·개인 일정은 공통 캔버스에 보내지 않는다.

최초 취향 분석 후 사용자는 수정한 내용과 현재 조건을 한 번에 저장하고 준비를 완료할 수 있다. 이미 저장된 내용은 저장 요청을 생략한다. 준비된 방장이 일정 만들기를 누르면 같은 입력의 결과를 다시 열거나 새 입력으로 경로를 만든다. 기존 별도 태그 재검토·생성 조건 확인 화면을 반복하지 않는다. 공통 조건 변경 안내와 CV/PV 확인, 입력 보존은 유지한다. 과거 공통 숙소·약속 문자열이 미해결인 방만 해당 값을 내 취향으로 옮기는 호환 안내를 표시하며 자동 저장·확정하지 않는다.

일정 만들기는 최신 준비 상태를 확인하고 기존 job을 시작하거나 진행 중인 작업을 이어서 조회한다. 현재 입력과 같은 완료 결과만 재사용한다. 조건이 달라진 이전 결과는 새로운 생성을 막지 않는다. [Skunkworks](https://skunkworks.co.kr/)의 전체 화면 전환 방식에서 시작한 밝은 배경과 팀 연두색을 유지하며, 후속 사용자 요청에 따라 실제 완료 단계만큼 채워지는 원형 게이지를 사용한다. 가짜 백분율이나 시간제 완료는 없다. 오류 시 입력을 보존하고, 가져오기 실패 재시도는 유료 생성 요청을 다시 만들지 않는다. 완료 후 모든 날짜의 경로 프레임을 한 화면에 배치한다. 자세한 후속 기준은 [원형 진행 표시와 생성 경로 보기](generation-progress-handoff.md)를 따른다.

실제 job 성공 후 OWNER의 POST /api/v1/trips/{tripId}/plans/{planId}/canvas가 새 버전의 코스로 공동 캔버스 전체를 교체한다. 기간 확대·축소·전체 날짜 이동에도 새 날짜·장소·연결·기본 배치만 남기고 이전 수동 장소·대안·댓글·날짜·배치는 제거한다. 검증·현재 source·revision 확인과 저장이 성공할 때까지 기존 캔버스를 유지한다. 같은 결과를 다시 열면 저장한 공동 편집·삭제를 유지하며 다시 초기화하지 않는다. FE는 새 source에서 이전 대기 편집과 undo/redo를 합치지 않는다. 최신 공동 문서를 확인한 뒤 같은 RoomPage의 캔버스로 이동한다. 생성 결과의 정식 저장과 공동 편집 초안은 구분한다.

서버·브라우저·실제 Gemini/Kakao는 agent가 실행하지 않는다. 사용자가 인접 BE run.py를 파이참에서 실행해 검수한다. 기준 계약은 [여행 준비](https://app.notion.com/p/412e977e49088197b345d73603c6a27f), [일정 생성·공동 캔버스](https://app.notion.com/p/413e977e4908817a9af9ca9c7fa0ddee), [공통 규칙](https://app.notion.com/p/40ee977e49088189b512e6e817984d48)이다.

실행한 검사와 사용자 검수 순서는 [최종 검증 기록](preparation-generation-validation.md)에 정리한다.
