# 여행 일정 생성 화면

[일정 생성·검토·저장 계약](https://app.notion.com/p/413e977e4908817a9af9ca9c7fa0ddee)과 [공통 규칙](https://app.notion.com/p/40ee977e49088189b512e6e817984d48)을 사용합니다. 기존 여행 준비 6개 API와 새 일정 생성 10개 API를 연결합니다. 개인 조건은 본인 전용이며 방장에게도 다른 참여자의 해석 근거를 보내지 않습니다.

## 실행

기존 Node 24 / npm 11 환경에서 `npm ci`, `npm run build`를 실행합니다. 개인 `.env.local`에 공개 JavaScript 키 `VITE_KAKAO_JAVASCRIPT_KEY`를 설정하고 변경 시 다시 빌드하세요. 카카오 JavaScript 도메인에 실제 접속 출처를 등록해야 합니다. REST 키와 Gemini 키는 FE에 넣지 않습니다.

인접 BE의 migration 001·002·003과 기존 계획 테이블을 먼저 준비해야 합니다. 앱은 migration을 자동 적용하지 않습니다. BE `run.py` 실행 후 `http://127.0.0.1:8017/`에서 사용할 수 있습니다. FE 개발 서버는 `npm run dev -- --host 127.0.0.1`, BE 허용 Origin과 기존 Vite 프록시를 확인하세요. AI 패키지는 BE 프로세스가 호출하므로 별도 AI HTTP 서버가 필요하지 않습니다.

## 확인 순서

1. 방을 만들고 여행 준비의 공통 조건을 저장합니다. 변경은 방장만 할 수 있습니다.
2. 각 참여자는 내 취향·제약에서 원문·정리 조건을 저장합니다. 원문 AI 해석 제안은 본인이 검토하고 반영한 뒤 별도로 저장합니다. 현재 버전의 조건을 직접 확정합니다.
3. 내 일정 조건 확인에서 확정 조건을 정규화하고, 제안 태그와 적용 범위·전체 의미를 본인이 검토합니다. 매핑되지 않은 조건은 원문을 고쳐야 합니다. 다른 사람은 완료 여부만 봅니다.
4. 여행 일정에서 방장이 09:00~18:00 기본 활동 시간을 수정하고 출발·복귀 WGS84 좌표와 필요한 숙박/고정 기준점을 저장합니다. 텍스트를 첫 검색 결과로 임의 변환하지 않습니다.
5. 모두의 현재 조건이 준비되면 방장이 초안을 생성합니다. 진행 상태는 서버 작업 ID로 조회하며 새로고침 후에도 다시 불러옵니다.
6. 목록·지도·상세는 동일한 노드 ID를 사용합니다. 실제 검증된 경로 geometry만 그리며 경로가 없으면 직선을 만들지 않습니다. 지도 오류 시 목록으로 계속 확인할 수 있습니다.
7. 알려진 위반은 저장을 막습니다. 미확인 항목은 방장이 확인란에 동의한 뒤 명시적으로 저장합니다. 현재 입력이 달라진 초안은 오래된 결과로 표시하고 저장하지 않습니다.

장소 요금이 없으면 '요금 확인 필요', 영업시간이 없으면 표시를 생략합니다. 전체 식비·유류비 등이 확인되지 않으면 총액은 알 수 없음이며 확인된 소계를 별도로 표시합니다. 표시 시간은 한국 시각입니다. 실제 변경 이력·복원은 범위 밖입니다.

## API 연결

공통 접두사는 `/api/v1/trips/{tripId}`입니다. 개인 저장·해석·직접 확정은 기존 `/preferences/me` 계열을 사용합니다. 새 화면은 GET `/generation`, GET/POST `/generation/preferences/me`, PUT `/generation/preferences/me/review`, PUT `/generation/settings`, GET `/generation/places`, POST `/generation/jobs`, GET `/generation/jobs/{jobId}`, GET `/plans/{planId}`, POST `/plans/{planId}/save`를 사용합니다.

현재 기기 쿠키와 same-origin 요청을 재사용하고 쓰기는 JSON/Origin을 사용합니다. 공통·개인·검토·설정·입력 토큰과 잠금 버전을 보내며 409에서 미저장 편집을 보존합니다. AI 제안은 편집·버전 변경 이후 자동 반영하지 않습니다. 권한 상실은 개인 화면과 대기 요청을 즉시 정리합니다.

이번 전달은 사용자 요청에 따라 로컬 Git 커밋만 수행하며 push·PR·추가 Notion 수정은 하지 않습니다.

로컬 검증(2026-11-09): npm run check(typecheck/lint/build), npm test 37개, git diff --check 통과. React effect/ref/dependency 경고 9건은 남습니다. 독립 Sol high 검토에서 발견한 버전 재확인, nullable 제안, 늦은 결과, 오류 재시도 루프, 권한 상실 DOM 정리를 수정했고 마지막 검토에 중요 지적은 없었습니다.

Chrome의 합성 여행방에서 원문 저장→AI 제안→직접 적용→별도 저장→직접 확정→정규화 검토→초안 생성→미확인 동의 저장→새로고침 복원을 확인했습니다. 별도 인앱 브라우저에서 초대 참여·저장 일정 조회·타인 원문 비공개·방장 버튼 미표시와 회원 비활성 후 개인 원문 제거를 확인했습니다. 모바일 breakpoint의 목록/대체 지도 표시와 가로 넘침 없음을 DOM 및 캡처로 확인했습니다. 검수는 격리 MySQL·가짜 AI/경로·전용 쿠키를 사용했습니다.

지도 SDK는 도메인 등록 안내 후에도 실제 401 domain mismatched가 남아 지도/마커/폴리라인의 실제 SDK 표시 검수는 미완료입니다. JavaScript 키의 JavaScript SDK 도메인에 `http://127.0.0.1:8017`을 등록해야 하며, 제품 링크 관리의 웹 도메인과 다릅니다. 지도 실패 시 목록과 상세는 사용할 수 있었습니다. 자동 검사는 실제 사용자 방이나 공용 DB를 사용하지 않습니다.
