# 세 참여자 취향으로 실제 일정 생성 검증

2026-11-11, FE 구현 `ea7f848`을 검증했다. FE 소스 변경 없이 실제 API 어댑터와 생성 시작 controller를 사용했다.

## 검수 조건

기기 쿠키를 분리한 세 참여자가 같은 방에 참여했다. 공통 조건은 청주시·2026-12-12 당일·3명·전체 60만원·도보다.

|참여자|직접 저장한 선호|걷기 조건|
|---|---|---|
|방장|자연|20분|
|참여자 B|카페|40분|
|참여자 C|전시|제한 없음|

실제 BE·AI와 격리 MySQL을 사용했다. 장소는 기존 합성 장소 1개와 자연·카페·전시 성격의 추가 검수 장소 6개다. 공용 개발 DB는 변경하지 않았다. 세 사람은 AI 해석 결과를 확인한 뒤 각자의 구조화된 선호·걷기 조건을 직접 저장·확정·검토했다.

## 결과

- 세 명의 서로 다른 저장본과 정규화 태그가 유지됐다.
- 마지막 참여자의 검토가 빠졌을 때 생성이 409로 차단됐다.
- 전원 검토 뒤 실제 AI 생성 작업이 `SUCCEEDED`로 완료됐다. 결과는 자연·카페·전시를 포함한 당일 7개 장소 코스였다.
- 생성 시작을 동시에 두 번 호출해도 POST는 한 번이었고, 동일 멱등 키 재호출은 같은 작업을 반환했다.
- 일반 참여자의 생성 요청은 403으로 차단됐고 공개 준비 상태·일정에 개인 원문·개인 점수가 노출되지 않았다.
- 경고를 명시적으로 확인한 뒤 저장했으며 세 참여자가 같은 `SAVED` 일정을 조회했다.
- 생성 작업·저장 일정의 source stamp를 읽기 전용으로 확인해 세 명 모두의 최신 확정·검토 버전이 사용됐고 그룹 스냅샷 인원이 3명임을 확인했다.

## 검증의 한계

필수 위반은 없었으나 이동 경로·도착 시간·도보 제한·영업시간·전체 비용은 자료 부족으로 `unknown` 경고가 남았다. 생성·3인 입력 반영·권한·저장 동작의 통과가 실제 관광지 추천 품질이나 모든 취향 조합의 충족을 보장하지는 않는다. 각자의 선호는 필수 제약이 아닌 선호 조건이다.

전체 FE 검사·화면 검증은 [일정 화면 검증 기록](itinerary-screen.md)을 참고한다. 실제 생성→저장→새로고침·지도 표시의 브라우저 검수와 이번 3인 API 검수는 구분한다. 검수용 세션 자격·AI 키·개인 환경 설정은 Git에 포함하지 않는다.
