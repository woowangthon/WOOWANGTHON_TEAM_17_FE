# 공동 캔버스와 기존 일정 생성 통합

2026-11-11, 원격 main의 PR #21 (`3051c73`)을 공동 캔버스 작업 브랜치에 병합했다. 새 일정 생성 모듈과 기존 보안·검토·저장 흐름은 유지하고, `RoomPage` 충돌에서는 현재 여행 준비 헤더·복사 알림·참여자 목록·왼쪽 탐색·공동 캔버스 진입을 보존했다.

## 사용 흐름

1. 사용자가 파이참에서 기존 BE 실행을 중지하고 `run.py`를 다시 실행한다. 브라우저에서 `http://127.0.0.1:8017/`을 새로고침한다.
2. 방장이 공통 조건을 저장하고 참여자는 각자의 취향을 저장·준비 완료한다. 본인의 일정 반영 조건도 직접 검토한다.
3. 방장의 **일정 만들기**는 서버의 최신 준비 상태를 다시 확인한다. 미저장 입력·진행 중 개인 처리·미완료 검토는 안내하고 자동 우회하지 않는다. 일반 참여자는 본인 검토로 이동한다.
4. 준비된 요청은 기존 BE 생성 작업을 시작하고 **여행 일정** 화면에서 진행 상태와 날짜별 코스를 확인한다. 활동 시간·출발/복귀와 필요한 공통 기준점은 기존 생성 조건 대화상자로 설정한다.
5. **일정 캔버스**는 기존 공통 헤더·사이드바 안에서 공동 초안을 편집한다. 생성된 코스를 캔버스로 자동 가져오는 기능은 이번 병합에 추가하지 않았다. 두 데이터의 저장·검증 경계를 유지한다.

## 환경과 검증

- 카카오 REST 키는 사용자 추가 후 BE 개인 설정에 존재함을 확인했다. 실제 경로 호출은 하지 않았다.
- 지도 표시용 `VITE_KAKAO_JAVASCRIPT_KEY`는 별도 공개 키다. 현재 FE 개인 설정에 없으며 지도 SDK가 없거나 실패해도 코스 목록과 상세를 확인할 수 있다. REST/AI 비밀키는 FE에 넣지 않는다.
- AI 저장소는 원격 main `7c2be6f`로 fast-forward했다. 기존 로컬 HEAD와 소스 차이가 없어 실행 코드는 바뀌지 않았다. BE 원격 main에는 추가 변경이 없었다.
- 최종 `npm run check`의 타입 검사·lint·빌드와 `npm test` 111개가 통과했다. lint 경고 8건은 이미 존재한 개인/일정 생성 모듈의 ref·effect·의존성 경고다. 이번 병합에서 해당 모듈을 수정하지 않았다.
- Sol high 독립 병합 검토에서 발견사항이 없었다. 기존 공동 캔버스의 충돌 처리·경로 대기 조회 검토도 유지한다.
- 사용자 지시에 따라 서버·브라우저·실제 AI/카카오 호출·공용 DB 쓰기는 실행하지 않았다. 이전 팀원의 3인 실제 API 검수는 [별도 기록](three-person-generation-review.md)이며 이번 병합의 실행 검증으로 대신하지 않는다.
