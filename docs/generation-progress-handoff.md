# 원형 진행 표시와 생성 경로 보기

회전하는 표시를 팀 연두색의 원형 게이지로 바꾼다. 게이지는 실제로 완료된 흐름을 네 단계로 표시한다. 준비 상태 확인 후 1단계, 경로 생성 후 2단계, 검증 후 3단계, 최신 공동 캔버스에 결과 반영 후 4단계다. 시간이나 임의 백분율로 차오르지 않으며 실패한 요청을 완료로 표시하지 않는다. 실제 단계 전환 때만 원을 채우고, 모션 감소 설정에서는 전환을 생략한다.

생성 결과를 가져오고 최신 캔버스 응답을 확인한 뒤 공동 편집 엔진에 반영한다. 처음 캔버스를 여는 방도 응답 데이터로 엔진을 준비한다. 기존 엔진의 미확인 저장은 같은 요청으로 확인하며 편집·멱등 키·실행 취소 이력을 덮어쓰지 않는다. 미해결 충돌이나 저장 실패는 캔버스 열기 단계에서 재시도하도록 안내한다. 경로 생성 요청은 반복하지 않는다.

완료 표시를 한 번 그린 다음 같은 방의 일정 캔버스로 이동한다. 공개 plan/version ID를 사용해 모든 날짜의 프레임을 함께 표시하고, 노드가 측정되면 새 경로 전체에 한 번 화면을 맞춘다. 이후 주기 조회·카드 이동·사용자의 날짜 선택이 화면을 계속 재정렬하지 않는다. 삭제한 생성 카드를 복구하거나 가짜 경로를 만들지 않는다. 기존 헤더·좌측 메뉴·지역 카드 높이와 공동 편집 동작은 유지한다.

날짜와 확대·이동 상태는 여행방 및 예시/실제 모드를 나눈 최대 100개의 메모리 항목에 보관한다. 같은 인계를 소비한 뒤에는 화면을 다시 맞추지 않고 기존 선택을 복원한다. 복원할 날짜가 사라졌으면 실제 남아 있는 경로를 선택한다. 빈 날짜의 화면 복원에는 노드가 아닌 viewport 준비를 사용한다. 성공한 최신 조회가 같은 revision을 반환해도, 미확인 쓰기나 충돌이 없는 조회 오류 상태는 복구할 수 있다.

이번 변경은 FE 표시와 화면 인계에 한정한다. 기존 job·가져오기·공동 캔버스 API 규격과 BE·AI 소스는 바꾸지 않는다. 서버·브라우저·유료 provider는 에이전트가 실행하지 않으며, 사용자가 기존 BE run.py로 검수한다. PR은 제목·본문 사용자 검수 후 반영한다.
