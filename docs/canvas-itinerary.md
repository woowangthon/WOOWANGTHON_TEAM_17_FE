# 캔버스 편집 일정 보기

현재 표시 기준은 마지막 `2026-11-14 최종 점검을 위한 전체 여행 종합` 절이다. 앞선 준비 화면 양식·사진 중심·행 안 상세 펼침 시안은 당시 기록으로 구분한다. 사용자 화면 검수는 기존 BE `run.py`로 진행한다.

사이드바의 `여행 종합`은 생성된 원본 대신 공동 캔버스의 최신 편집 문서를 읽는다. 기존 `view=itinerary` 주소는 유지한다. 캔버스의 현재 저장 대기 편집도 목록과 지도에 반영하며, 날짜별 장소·선택 상세는 실제 캔버스 노드 ID와 연결을 기준으로 동기화한다. 캔버스의 순서 연결은 `GET /api/v1/trips/{tripId}/canvas/route`로 다시 확인한다. 기존 계약의 지도 경로 geometry 옵트인 헤더를 사용하고, 응답의 source/target·conditionsVersion·mode가 현재 간선과 일치하는지 기존 parser가 검증한다. 새 endpoint나 서버 데이터는 추가하지 않는다.

지도에는 응답이 `verified`이고 실제 경로 좌표가 검증된 간선만 그린다. 오래된 캐시, 미확인 응답, 조회 실패, 좌표 없는 verified 응답은 선을 만들지 않는다. 사용자별 브라우저 간선 이동 설정은 공통 이동수단보다 우선한다. 직접 입력한 시간은 자동 확인 시간과 구별해 목록에 표시한다. 지도 좌표가 없는 장소도 장소 목록·상세는 유지한다.

예상 비용은 원화와 적용 단위가 명확한 안내만 저장된 예정 인원·현재 방문 범위로 합산한다. 합산할 수 없는 장소·이유·검색은 금액 옆 `!`의 `예외 항목`에서 보여 주며 모르는 금액을 0원으로 만들지 않는다. 가져온 방문 시각은 생성 당시 예상이며 캔버스 편집 뒤 자동 재계산하지 않는다. 연결되지 않은 코스는 별도 묶음으로 보여주며 임의 선으로 연결하지 않는다. 장소 상세 조회 실패는 장소별 재시도를 제공한다. 종합 화면의 지도 SDK 오류·좌표 누락은 평문 상태로 표시하고 임의 번호 배치나 연결선을 만들지 않는다. 기본 생성 화면의 지도 표시 방식은 별도로 유지한다.

## 준비 화면 양식을 재사용한 이전 종합 시안

사용자가 앞선 `f5ea454` 시안의 버튼 형식과 종합 화면을 반려해 `8cdee72`에서 준비 화면의 실제 클래스와 정보 구획을 재사용했다. 사용자는 이 종합 구성도 다시 제작하도록 요청했다. 아래는 해당 시안의 기능·정적 화면 검사 기록이며 현재 디자인 기준이나 사용자 승인 기록이 아니다.

## 2026-11-14 최종 점검을 위한 전체 여행 종합

사용자는 캔버스에서 직접 만든 여행의 전체 일정·지도·이동 시간·비용을 한꺼번에 최종 점검하는 역할을 명확히 했다. 긴 장소 설명이 다음 방문을 밀어내던 구성 대신, 날짜별 코스와 지도 및 선택 장소 상세를 독립된 영역으로 배치한다. 기존 밝은 바탕·Pretendard·연두 포인트·공통 헤더/좌측 탐색/실행 버튼을 유지한다. 새 API·BE·AI·DB·일정 생성 알고리즘은 변경하지 않는다.

- 첫 진입은 `전체 일정`이다. 모든 날짜를 날짜별 목록과 한 지도에 표시하고 날짜 선택으로 같은 범위를 좁힌다. 선택 범위의 방문 번호는 지도와 목록에서 일치한다. 같은 장소의 중복 방문, 빈 날짜, 분리된 코스와 실제 연결 순서를 보존하며 날짜 사이 선을 임의로 추가하지 않는다.
- 요약은 표시 중인 범위의 일정 점검, 제공된 체류 시간, 확인된 이동 시간과 확인 범위, 예상 비용의 확인 동작을 보여준다. 유효한 직접 입력을 우선하고 자동 조회는 현재 구간의 양 끝 장소·이동수단·공통 조건 버전이 일치할 때만 시간으로 반영한다. 확인된 이동 시간은 geometry가 없어도 읽을 수 있으나 지도 선은 검증 geometry가 있을 때만 그린다.
- 누락된 시간은 0분이나 완전한 합계로 표시하지 않는다. 직접 입력 시간의 포함 여부와 미확인 방문/구간을 구분한다. 체류와 이동을 단순 합산해 하루의 시작~종료 소요 시간으로 만들지 않는다. 기존 방문 시각은 생성 당시 예상이며 캔버스 편집 뒤 재계산된 시각으로 주장하지 않는다.
- 현재 편집 모델의 요금은 문자열이다. 사용자 후속 요청에 따라 전체 문장이 명시적 원화·단위 문법과 일치하는 안내만 예상 장소비로 합산한다. 저장된 예정 인원과 방문 범위를 적용하고 불명확한 비용을 0원으로 만들지 않는다. 금액·근거·제외 이유·검색은 상단 팝오버에서, 원문 전체는 선택 상세에서도 읽는다. 세부 기준은 아래 `방문별 상태 팝오버·명시 요금 합산·사진 상세` 절을 따른다.
- 왼쪽은 시간·장소·머무는 시간·요금과 다음 이동을 짧게 표시하고, 선택 상세를 행 사이에 넣지 않는다. 지도 아래에 선택 날짜·방문 번호·장소명과 공개 장소 정보를 한 번만 표시한다. 긴 상세는 제한된 본문 안에서 읽으므로 요금/소개를 펼쳐도 일정 행과 지도가 밀리지 않는다. 휴대폰도 별도 상세 영역을 유지하며 지도·상세·목록 사이에 명확한 이동과 초점을 제공한다.
- 실제 공동 캔버스의 현재 편집 문서를 읽으며 저장 대기/오류/충돌·재시도와 구간별 이동 설정을 유지한다. 장소 상세는 필요한 범위에서 최대 네 요청씩 불러온다. 새 공개 정보가 도착하면 순차 반영하고, 오래된 범위의 응답은 무시한다. 메모와 독립 후보는 날짜별 참고 내용으로 구분한다.

참고: [TripMapper 공개 여행 일정](https://discover.tripmapper.co/trip/two-days-in-prague-bc40)의 날짜별 정보 묶음과 [Tripomatic 일정 안내](https://support.tripomatic.com/editing-your-trip/working-with-the-itinerary.html)의 체류/이동 구분을 참고했다. 다른 서비스의 자산·색상·편집 기능은 복사하지 않는다. 세부 기준은 [UI 가이드](ui-guide.md)를 따른다.

### 장소 정보 가독성과 상단 비용 제목 후속

추가 요청으로 상단 `요금 안내` 제목은 `예상 비용`으로 바꾸고, 현재 편집 문서의 금액 합계가 없으므로 주 값은 `미산출`, 보조는 요금 안내가 있는 방문 수로 표시한다. 방문이 없을 때는 `방문 없음`이며 0원이나 0/0을 만들지 않는다. `여행 범위`를 대체할 통계는 사용자가 후보 목록을 먼저 요청해 선택 대기다. 임시로 준비했던 일정 구성 helper/검사는 제거하고 상단 첫 항목은 유지한다.

Sol high 계획 → Luna high 선택 상세 구현 → root 소스 검토/정렬 보완과 비용 문구 반영을 수행했다. 최종 `npm run check`(오류 0, 기존 다른 파일 경고 25)·기존 테스트 208개·공백 검사를 통과하고 실행용 빌드를 갱신했다. 서버·브라우저·listener를 실행하지 않았으며 실제 화면의 확인은 사용자 `run.py` 검수로 남긴다. 경로/비용 알고리즘·BE·AI·DB에는 변경이 없다.

### 일정 점검과 행동으로 이어지는 요금 확인

사용자는 상단 첫 통계로 `일정 점검`을 선택했고, 비용의 막연한 미산출 안내 대신 근거 있는 추정값이나 검색을 원했다. 기존 공동 캔버스와 표시 중인 날짜 범위를 기준으로 다음 항목만 점검한다.

- 장소 정보 조회가 실패한 방문: 정보 다시 불러오기.
- 조회된 공개 장소 정보에 유효한 WGS84 위치가 없는 방문: 장소 선택/외부 위치 검색.
- 현재 조건·이동수단·출발/도착 장소가 일치하는 검증 이동 시간이 없는 구간: 구간 확인/명시적 다시 조회. 유효한 직접 입력은 인정하고 0초의 검증 시간도 유효하다. 도로 geometry가 없다는 이유만으로 시간 오류로 세지 않는다.
- 같은 날짜의 두 번째 이후 분리된 코스: 시작 장소에서 연결 확인. 의도적인 분리일 수 있으므로 일정 오류로 차단하거나 자동 연결하지 않는다.

조회 진행 중은 점검 결과와 구분한다. 예시 화면은 실제 경로 조회 전임을 구분하고, 후보·댓글·날짜 사이 빈틈은 이 점검에 섞지 않는다. 점검 항목에는 날짜/방문/구간 식별을 유지하며 기존 방문으로 선택·스크롤·키보드 초점 이동을 제공한다. 이 확인은 위치·코스 연결·공개 정보/이동 시간 조회 기준이며 영업시간·시간 충돌·예산 검증 완료를 뜻하지 않는다. 기존 경로 훅은 요청/캐시/재시도 동작을 바꾸지 않고 현재 요청 범위의 단계만 추가 노출한다.

상단 `예상 비용`은 `요금 확인하기`로 방문별 원문 안내와 외부 검색에 연결한다. 공급된 `1인 약 N원`, 입장료, 1박/기준 인원 등은 원문 그대로 표시한다. 가격 문장을 숫자로 파싱하거나 임의 식비/숙박비를 넣어 합산하지 않으며 옛 생성 계획의 비용을 현재 편집 일정의 총액으로 재사용하지 않는다. BE 코드를 읽어 확인한 결과 현재 캔버스 API는 정형 가격을 문자열 `priceLabel`로만 내려주므로, 현재 합계 금액을 만들려면 금액·단위·기준 인원·출처를 가진 별도 계약이 필요하다. 이번 변경은 FE의 요금 확인/검색 동작이다.

요금 또는 위치 검색은 고정 HTTPS 네이버 검색 주소에 공개 장소명·도시·주소와 검색 목적만 인코딩한다. 장소 정보를 불러오지 못한 방문은 다시 불러오고, 조회된 정보에 장소명이 없는 방문은 캔버스에서 장소를 확인하도록 한다. 숫자 ID로 검색하거나 재시도가 동작하지 않는 버튼을 만들지 않는다. 방 이름·초대 코드·여행방 ID·개인 원문/취향은 외부 검색에 포함하지 않는다. 제공된 안전한 공식 홈페이지도 확인 경로로 사용한다. 검색은 사용자 링크 선택으로만 열고 자동 조회하거나 검색 결과를 검증했다고 주장하지 않는다. 외부 링크는 새 창과 안전한 rel 속성을 사용한다.

Sol high 선행 계획 → Luna high 모델/화면 분담 → root 통합과 별도 Sol high 소스 검토를 수행했다. 검토로 발견한 예시의 실행되지 않는 조회 대기 표시와 공통 조건이 없을 때의 무효 재조회 동작을 수정했다. 전체/날짜 범위, 반복 방문, 직접 입력/검증 0분, 오래된 경로 배제, 진행/실패 구분, 누락 위치, 외부 검색의 공개 필드 제한을 포함한 모델 검사 22개와 전체 테스트 214개가 통과한다. 최종 `npm run check`의 타입·lint·실행용 빌드가 통과하며 오류 0개와 다른 기존 파일의 경고 25개다. 기존 `CanvasPreview.tsx`와 `ResultMap.tsx`는 작업 전후 해시가 동일하다. 서버·브라우저·제품·외부 검색·실제 API/DB는 실행하지 않았고, 화면 배치와 키보드 실동작은 사용자 `run.py` 검수로 남긴다. 커밋·push·PR은 수행하지 않았다.

### 방문별 상태 팝오버·명시 요금 합산·사진 상세

사용자가 본문 펼침 대신 마우스를 올리는 팝업, `상태 아이콘 | 어떤 장소인지`, 명시된 요금의 예상 합계, 사진을 포함한 하단 정보 정리를 요청했다. 앞 절의 `요금 확인하기`와 본문 펼침 규칙보다 이 후속 기준을 우선한다.

- 점검 팝오버는 완료 방문도 포함해 아이콘·장소명·일차·분류를 보여 준다. 각 방문의 공개 위치·장소 정보와 다음 실제 구간의 이동 시간 상태를 사용한다. 마지막 방문에는 존재하지 않는 다음 구간을 요구하지 않는다. 의도적인 별도 코스는 안내로 유지하며 예시는 실제 점검 완료로 표시하지 않는다.
- 점검과 금액은 hover·키보드 초점·터치로 여는 오버레이다. 본문을 아래로 밀지 않고 한 번에 하나만 열며, trigger와 내용 사이를 오갈 수 있다. Escape·영역 밖 선택·표시 범위 변경으로 닫는다. 내부에 실제 조작이 있으므로 단순 tooltip 역할로 표시하지 않는다.
- 비용 모델은 `canvasItineraryCosts.ts`의 순수 계산이다. `priceLabel`·`feeText` 전체가 명시적 1인/전체 원화 또는 무조건 무료 문법과 일치할 때만 합산한다. 전체 금액은 `전체 1회`도 인정하지만 `1회`만 있는 가격은 인원 기준을 알 수 없어 제외한다. 저장된 `expectedPeople`을 전달하며 참여자 수나 저장하지 않은 폼 값으로 대신하지 않는다. 범위는 하한·상한을 따로 더하고 공급된 `약`의 의미를 보존한다. 같은 의미의 두 안내는 한 번만 계산하고 동일 장소를 다시 방문하면 방문별로 센다.
- 숫자만 있는 요금·조건부 무료·연령/메뉴 선택지·서로 충돌하는 요금·박수와 객실 수를 알 수 없는 숙박·다른 통화는 추측해 더하지 않는다. 합산 가능한 방문이 없으면 금액 없음 상태이고, 일부만 확인되면 확인 수와 제외 이유를 표시한다. 무료 0원과 모르는 금액을 구분한다. 표시 금액은 장소비 기준이며 교통/추가 지출은 별도다. 팝오버에 산출 기준·원문·검색을 남기고 이전 생성 계획의 합계는 사용하지 않는다.
- 지도 아래는 해당 장소의 실제 사진, 분류·주소, 방문/체류·요금, 메뉴/운영, 연락/편의의 순서로 읽는다. 사진 실패나 부재에는 사진 영역을 접고, 긴 설명과 요금은 원문을 보존한다. 전체 일정 목록과 큰 지도, 공통 준비 화면의 헤더·탐색·버튼은 유지한다.

참고한 공개 자료는 [Tripomatic 장소 정보](https://tripomatic.com/en/features/places-to-visit)의 사진·운영·주소·연락 정보 구분, [TripMapper 기능](https://www.tripmapper.co/features)의 지도와 목록 역할 구분, [Towards](https://towards.co.kr/)의 제목과 목록 구성이다. BE·AI·DB·API 계약은 변경하지 않았고 서버·브라우저·제품·외부 검색을 실행하지 않았다. 실제 hover/키보드/터치·사진·반응형 배치와 실 API/공용 DB 검수는 사용자 실행으로 남긴다. 커밋·push·PR은 수행하지 않았다.

### 미완료·비용 예외만 표시하는 후속 정리

사용자가 실제 화면을 검수한 뒤 장소 정보 높이 확대, 완료 행 제거, 금액만 표시하고 느낌표에서 비용 예외를 보는 구성을 요청했다. 위 절의 완료 방문 포함과 금액 전체를 여는 동작보다 이 기준을 우선한다.

- 장소 상세는 고정 280px 대신 자연 높이와 최대 460px로 더 많은 정보를 한 번에 읽는다. 짧은 내용에 빈 높이를 강제하지 않으며 긴 원문에만 내부 스크롤을 유지한다. 지도·목록 열을 보존하고 낮은 화면에서는 커진 묶음을 고정하지 않는다.
- 점검 팝오버는 실제 `needs-review`/`loading` 방문만 나열한다. 완료 방문은 별도 코스 finding이 있어도 목록에서 숨기며 기존 요약·코스 구분 안내는 유지한다. 실제 미완료 없음·방문 없음·예시를 구분한다.
- 예상 비용은 숫자/범위와 원만 표시하고, 합산 불가 또는 방문 없음은 `—`로 표시한다. `확인된 비용`·`약`·아래 캡션을 주 값에서 제거한다. 계산·추정 메타데이터를 삭제하지 않고 저장 인원·합산 범위·교통/추가 지출 제외와 함께 `!` 팝오버로 옮긴다.
- 금액은 일반 텍스트이며 `!` 버튼에 hover·초점·터치·키보드 진입과 위치 anchor·Escape 복귀를 연결한다. 예외 목록은 `basis === 'unknown' || minKrw === null || maxKrw === null`인 방문만 표시한다. 정상 무료/정상 합산 행은 숨기고, 예외 장소·이유·원문·네이버 검색/재시도/캔버스 확인을 유지한다. 실제 0원과 모르는 금액을 구분하며 부분 합계·예외 수·예시 의미도 버튼 접근성 이름에서 알린다.

이번 후속은 두 UI 파일과 기준 문서만 변경하며 비용 계산·방문 점검 모델·저장 인원·API·BE·AI·DB는 수정하지 않는다. 기존 hover 유예·키보드/터치·범위 변경 닫기·예약 작업 정리·화면 안 배치와 사용자 `run.py` 실행 범위는 유지한다.

별도 GPT-6.1 Sol high 계획 → Luna high UI 구현 → root 통합 및 GPT-6.1 Sol high 독립 소스 검토를 수행했다. 새 조치 필요 사항은 없으며 로딩 중 장소에 최종 요금 부재 사유를 잘못 표시하던 문구도 보완했다. 최종 `npm run check`(오류 0, 기존 다른 파일 경고 25)·테스트 221개·공백 검사를 통과하고 실행용 빌드를 갱신했다. 비용/점검 모델·저장 인원 전달·기존 캔버스/지도/경로 훅은 전후 해시가 동일하다. 서버·브라우저·제품 실행과 실제 화면/키보드/터치 검수는 수행하지 않았으며 사용자 `run.py` 확인으로 남긴다. 커밋·push·PR은 하지 않았다.

### 날짜 가이드 제거와 점검·비용 예외 정렬

사용자가 두 번째 스크린샷의 문제를 수치 불일치가 아닌 `1회 확인 필요`의 단어 선택과 아래 강조선 정렬이라고 명확히 했다. 점검 문구를 `확인 필요 N건`/`확인 중 N건`으로 바꾸고 네 요약의 주 값을 같은 최소 44px 영역에 맞춘다. 점검 강조선은 텍스트 바로 아래에 붙이며 점검·비용 계산은 변경하지 않는다.
