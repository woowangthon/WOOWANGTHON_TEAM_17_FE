# 여행 준비 입력 정리

최신 후속 기준은 [여행 준비 상태와 최종 로컬 검수](preparation-confirmation-review.md)를 따른다. 참여자 공개 상태 통일·직접 준비 완료·이동수단 라디오·`내 취향` 이름과 새 BE 병합본 유지가 적용됐다. 마지막 사용자 지시 이후에는 서버·브라우저를 실행하지 않으며 아래의 화면 검증 기록은 이전 수정본의 기록이다.

사용자의 12개 수정 요청에 따라 여행 준비 화면을 정리한다. 시작 화면과 일정 캔버스, 기존 API 계약을 유지하며 이번 작업에서 서버 실행·커밋·push·PR·공용 DB 변경을 하지 않는다. 완료 후 사용자가 BE의 `run.py`로 실행한다. PR은 제목과 본문을 먼저 검수받는다.

## 화면과 입력

- 왼쪽 아이콘 레일의 탐색 내용은 오버레이로 열며 중앙 입력 영역의 위치와 폭을 바꾸지 않는다.
- 상단 버튼 묶음은 참여자 이름과 서버 준비 상태로 대체한다. 실시간 접속 여부나 AI 저장을 서버 확정으로 표시하지 않는다.
- `여행 기본조건`의 공유 설명은 작은 정보 아이콘으로 옮긴다. 마우스, 키보드와 터치로 읽을 수 있어야 한다.
- 지역은 직접 타이핑하는 대신 처음부터 열린 가로 목록에서 `충북 어디든` 또는 시군을 고른다. 선택 요약은 현재 입력값을 즉시 반영한다. 마우스 드래그·터치 스와이프·키보드로 목록을 탐색한다. 선택하지 않은 값을 자동 저장하지 않으며 이전 문자열도 보존한다.
- 숙박과 고정 일정은 기본 화면에서 제거한다. 기존 저장값은 최신 공통 조건에서 가져와 보존하므로 다른 조건을 저장하거나 충돌을 재적용해도 되돌리지 않는다.
- 개인 영역 제목은 `정보 입력`으로 바꾼다. 지정된 반복 설명 두 문장은 제거한다.
- 중요도 선택창은 `반드시 피해야 해요`, `꼭 지켜야 하는 식사 조건이에요`처럼 실제 뜻을 설명하는 체크 항목으로 바꾼다. 체크와 기존 `required`/`preferred` 값의 의미는 그대로 유지한다.

## 분석의 상태

입력 영역 안에서 실제 요청의 단계만 표시한다. 원문 PUT → 해석 POST → 결과 PUT 순서이며 가짜 진행률·지연·타이핑 효과를 넣지 않는다. 첫 분석의 최종 저장이 성공하면 정리한 취향을 표시한다. 한 번 표시한 편집 영역은 원문·취향 수정, 저장, 재분석, 재조회와 복구 가능한 오류 중에도 유지한다. 재분석 결과는 마지막 저장이 성공한 뒤 교체한다. 이전 결과를 최신 해석처럼 표시하지 않고 재분석 가능 상태를 따로 안내한다.

이전 저장본은 `저장된 내용`, 이번 분석 완료는 `분석 완료`로 구분한다. 현재 서버는 원문과 해석값 사이의 분석 출처를 별도로 제공하지 않으므로 재접속한 저장본이 최신 AI 결과라고 주장하지 않는다. 비어 있는 취향을 저장하고 새로고침해도 편집할 수 있도록 저장 버전이 있는 응답은 저장본 편집 영역을 제공한다. 실패한 요청은 원문과 기존 취향을 보존하며, 공통 조건 변경으로 분석을 취소하면 내부 처리 상태도 종료한다. 권한 상실·여행방 변경 시에는 개인 값을 숨기고 초기화한다. 직접 검토 확정 API를 자동 호출하지 않는다.

## 참고와 자료

시작 화면의 로컬 Pretendard·밝은 표면·연두 포인트·사진·버튼 형태를 재사용한다. 정보 구조는 작업 화면에 맞게 단순화한다. 사진은 기존 시작 화면의 한국관광공사 DB 자료를 사용한다.

- [SKUNKWORKS](https://skunkworks.co.kr/): 현재 화면 캡처와 내용 확인. 큰 글자·간결한 탐색과 진행 상태의 분리를 참고한다.
- [GDWEB](https://www.gdweb.co.kr/main/index.asp): 현재 갤러리와 선정작 목록 확인.
- [Towards](https://towards.co.kr/): 재조회 시 timeout/DNS 오류. 새 화면을 확인했다고 주장하지 않으며 기존 검수한 시작 화면과 앞선 참고 자료를 활용한다.
- [Masstige 참고 페이지](https://geo.masstige.biz/#diagnosis-records): 텍스트 조회 결과는 비어 있어 세부 화면을 검증했다고 주장하지 않는다.
- [충청북도 공식 통계 자료](https://chungbuk.go.kr/site/stat/img/content/sub01/1.pdf), [충북소방본부 시군 목록](https://cb119.chungbuk.go.kr/home/sub.do?menukey=2931): 청주·충주·제천과 8개 군의 선택 목록을 확인한다.

## 최신: 사진 지역 선택·본인 저장 상태

마지막 사용자 수정에 따라 별도 시군 드롭다운을 제거했다. 현재 선택값을 표시하는 버튼 하나로 카드 영역을 열고 닫으며 기본은 열린 상태다. 맨 앞 `충북 전체` 카드와 11개 시군 사진 카드가 이어진다. 마우스 드래그·휴대폰 스와이프·키보드 선택을 지원하며 선택한 카드는 세로 위치를 건드리지 않고 가로로만 보이게 한다. 기존 raw/canonical 값, legacy 문자열, 미선택 상태를 보존한다.

두 영역의 배경색을 제거하고 제목 기준선과 구분선을 맞췄다. 조건 저장은 입력 아래 오른쪽으로 옮겼다. 참여자는 이름과 상태를 가까이 묶으며 본인 저장 상태는 개인 응답으로 구분한다. `저장됨`은 초안 저장이고 `확인 완료`는 서버의 직접 검토 확정이다. 다른 사람은 공개된 확인 상태만 표시한다. 확정 API나 자동 검토 처리는 추가하지 않았다.

공통 조건 안내는 개인 hook의 조건 버전과 현재 공유 버전이 다를 때 나온다. 편집 중이면 입력을 유지하며 재조회가 필요하다고 한 번만 안내한다. idle 상태에 분석 중단 문구를 쓰지 않는다. 조건 불일치 중에는 별도의 개인 입력 변경 안내를 중복 표시하지 않는다. 저장본 재조회 버튼은 미저장 입력을 대체함을 명시한다.

사진은 `chungbuk_trip1.places`를 읽기 전용으로 조회해 11개 시군을 확인했다. 기존 6개 지역 사진을 재사용하고 보은·옥천·영동·증평·음성 5개 사진을 해당 행의 한국관광공사 원본에서 추가했다. 전체 카드의 콜라주는 실제 청주·충주·제천 사진이다. 사진별 DB 키와 원본 출처는 `src/features/preparation/regionPhotos.ts`에 있다. 사용자 화면이 DB를 직접 조회하는 구조는 아니다.

최종 검증은 `npm run check`, 46개 Node 검사, 22개 모의 API 브라우저 검수가 통과했다. 12개 카드·드롭다운 제거·열고 닫기·실제 11개 사진 로드·사진 실패 시 지역 선택·선택값 보존, 저장/확정 구분, 공통 조건 변경의 단일 안내, 기존 취향 유지·권한·충돌·모바일 검수를 포함한다. 독립 검토 지적을 수정하고 재검증했다. 디자인 검사 0 FAIL / 0 REFLEX / 0 WARN, 사진 카드 크기는 사용자 요구에 따른 39b 예외 1개를 기록했다. `.hallmark/preparation-photo-status/`에 캡처와 검사 기록이 있다.

BE·AI 소스, 공용 DDL·DB 데이터·Notion 원문을 수정하지 않았다. 서버 시작·재시작, 실제 AI 호출, 커밋·push·PR을 수행하지 않았다. 사용자는 빌드된 화면을 기존 BE `run.py`로 확인한다. 아래 검증은 이전 단계 기록이며 이 최신 후속 기준을 우선한다.

## 취향 유지·지역 선택 후속 수정

정리한 취향이 사라진 직접 원인은 `RoomPage`가 최신 상태(`stored`/`analyzed`)이면서 처리 중이 아닌 경우에만 결과 입력을 렌더링한 것이다. 원문 변경의 `stale` 상태와 저장·재분석 phase가 입력칸을 제거했다. 일반 공통 준비 새로고침은 기존 스냅샷이 있으면 `ready`를 유지하므로 그 자체가 초기화 원인은 아니다.

표시 수명(`resultsVisible`)을 분석 최신 상태와 분리했다. 첫 분석의 최종 저장 후 나타난 취향 입력은 같은 여행방에서 수정·저장·재분석·복구 가능한 실패·재조회 중에도 유지한다. 권한 상실·여행방 변경 시 개인 데이터는 초기화한다. 데이터 계약·확정 상태·저장 버전 검사는 유지한다.

- 지역은 기본으로 열린 12개 가로 선택지로 변경했다. 선택 요약이 실제 입력을 반영하며 드래그와 스와이프는 선택 변경과 분리한다. 사진 예시·접이식 지역 메뉴·중복 드롭다운은 제거했다.
- 참여자 이름과 상태를 한 묶음으로 표시하고 구분선을 추가했다. 공통/개인 영역 머리글은 얕은 배경으로 구분한다.
- 헤더의 중복 방 이름, 메뉴 안의 중복 방 이름, 큰 테두리 닫기 버튼을 제거했다. 본문 여행 제목은 유지한다.
- 분석·저장 버튼은 오른쪽에 배치하고 8px 모서리의 사각형으로 정리했다.

최종 검증:

- `npm run check` 통과, `npm test` 40개 통과.
- 모의 API 브라우저 검수 18개 통과. `MutationObserver`로 최초 분석 이후 원문·취향 수정, 저장, 재분석의 POST/최종 PUT 대기, AI 503, 개인 409와 재조회 중 취향 입력칸이 한 번도 제거되지 않음을 확인했다.
- 비어 있는 저장본·분석 결과의 편집과 새로고침 복원, 최신 숨긴 공통 조건 보존, 403 개인 입력 숨김을 확인했다. 서버 확정 요청은 호출하지 않았다.
- 지역 실제 마우스 클릭, 드래그 후 오선택 방지, 바깥에서 버튼을 놓고 돌아왔을 때 스크롤하지 않음, 마지막 선택지 키보드 선택, 휴대폰 실제 터치 이벤트 스와이프를 확인했다.
- 1440/900/390px 가로 넘침 없음. 모바일 분석·저장 버튼의 오른쪽 정렬과 도움말을 확인했다. 독립 검토가 소스와 실제 컴퓨터·휴대폰 캡처를 확인했다.
- 디자인 검사에서 실제 간격 문제를 수정했다. 최종 렌더 검사에는 73번 한 건이 남는다. 검출기가 가로 스크롤 영역 밖 텍스트 좌표를 인접 패널의 글자 겹침으로 오인한다. 캡처 및 독립 검토에서 선택지 텍스트는 스크롤 영역 경계에 잘리고 옆 영역에 그려지지 않음을 확인했다. 자동 렌더 검사를 전체 통과했다고 보고하지 않는다. 결과는 `.hallmark/preparation-stability-design-check.txt`에 기록했다.
- 증거: `.hallmark/preparation-stability/verification.json` 및 같은 폴더 캡처. 이 검수는 모든 요청을 가로채며 서버 신규 실행·실제 AI 호출·공용 DB 저장·커밋·push·PR을 수행하지 않았다.

## 사용자 실행

FE 빌드를 완료했다. PyCharm에서 기존 BE `run.py` 구성을 사용해 사용자가 실행한다. `http://127.0.0.1:8017`에서 시작하고 방에 들어가 여행 준비를 확인한다. 이미 실행 중이면 새로고침한다. 서버의 기존 환경 설정·인증·DB·Gemini 준비 상태를 그대로 사용한다.
