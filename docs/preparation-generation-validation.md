# 준비 → 생성 → 공동 캔버스 검증 기록

2026-11-11 현재 로컬 구현과 원형 진행 표시 후속 변경의 기록이다. 원격 PR 갱신·병합·서버 기동은 수행하지 않는다. 새 흐름과 검수 기준은 [기능 설명](preparation-schedule-design.md)과 [원형 진행 표시·경로 인계](generation-progress-handoff.md)를 따른다.

- FE: npm run check(타입·lint·빌드) 통과, npm test 135개 통과. Lint 오류 0, effect/ref/dependency 경고 10건. 원형 로딩 컴포넌트 정적 디자인 검사 0 FAIL/0 REFLEX/0 WARN. 브라우저 렌더 검사는 실행하지 않았다.
- BE: 인접 저장소의 pytest -m 'not mysql' 178개 통과, MySQL 172개 제외. in-process SQLite와 fake AI/router를 사용했다. Starlette/httpx·SQLite datetime adapter 경고가 남는다. 공용 DB는 관련 테이블 DDL만 읽기 전용으로 확인했으며 데이터 쓰기·초기화·migration은 실행하지 않았다.
- AI: 인접 패키지의 unittest 51개 통과. 실제 HTTPS 호출 없이 최초 분석의 근거·미예약 상태·오전/오후·상대 날짜·알 수 없는 항목을 검사했다.
- 검토: 별도 GPT-6.1 Sol high 계획, Luna high FE/BE 구현, root 통합 및 별도 Sol high 독립 검토. 오전/오후 시각, 미예약 숙소, 체크아웃만 알려진 경우, 숙소 범위 누락, 하루 8개 초과 약속 누락의 지적 5건을 수정하고 재검토에서 해소했다.

원형 게이지 후속은 FE만 변경했다. 위 BE·AI 수치는 이전 기능 커밋 849ca83/f2ce744의 검증 결과이며 이번 후속에서는 해당 소스를 바꾸지 않았다. 단계 기반 채움, 오류 시 미완료, 완료 프레임의 취소·늦은 응답 무시, 최초 엔진 준비, 미확인 PUT의 같은 키 재시도, 최신 편집 보존, 생성된 날짜 선택과 화면 상태 복원을 확인했다. 추가 독립 검토에서 발견한 연결선 삭제 ID 회귀, 같은 revision의 조회 오류 복구, 재진입 시 중복 화면 맞춤, 빈 날짜의 화면 복원 문제를 수정·재확인했다. 화면 복원은 viewport 준비를, 경로 맞춤은 노드 측정을 기다린다. 실제 UI 렌더 검수를 수행한 결과로 표현하지 않는다.

응답 유실 시 같은 키 재시도, 실제 완료 전 캔버스 이동 금지, 변경된 입력의 이전 결과 재사용 방지, OWNER 권한, 공동 편집 보존·CAS, 가져오기 중복·삭제 후 복구 방지와 메타데이터 위조/정상 undo를 확인했다. 숙소는 검증된 장소 집합을 바꾸지 않고 당일 마지막으로 배치하며, 퇴실일을 추가 숙박으로 만들지 않는다. 모르는 이동 시간·가격·체크인 시각을 만들어 넣지 않는다.

수동 검수는 파이참에서 인접 BE의 기존 run.py를 실행한 뒤 http://127.0.0.1:8017/ 에서 한다. 이 작업의 빌드가 FE dist에 준비되어 있으므로 별도 AI 서버는 필요 없다. 기본조건 저장 → 내 취향 분석·저장 → 모든 참여자 준비 완료 → 방장 일정 만들기 → 전체 로딩 → 같은 방 공동 캔버스 순서로 확인한다. 개인 원문·개인 일정은 본인 화면에만 표시되는지 두 기기로 확인한다.

실제 Gemini/Kakao 응답·MySQL 쓰기/경합·모바일/키보드 렌더·두 기기 실사용 검수는 수행하지 않았다. 이 미실행 항목을 실제 통합 검증 완료로 표현하지 않는다. PR 제목·본문은 사용자 검수 후 갱신한다.
