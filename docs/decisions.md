# 초기 구성 결정

2026-11-03

- React + TypeScript + Vite + Tailwind, npm과 단일 package-lock.json을 사용한다.
- Node 24.x를 package.json engines에 기록하고 실제 개발 기준은 README에 적는다. 사용자 선택에 따라 .node-version은 추가하지 않는다.
- 초기 범위는 실행 환경·공통 UI 확인 화면·팀 문서·에이전트 설정·이슈/PR 양식이다. 여행 기능·API·배포는 별도 작업이다.
- 공통 UI는 소스로 관리한다. 기존 Mantine 예제와 원본 노션 내보내기·압축파일은 레포에 복사하지 않는다.
- 개인 원문 본인 전용은 UI 설계의 초기 기준이다. 방장 접근·인증·서버 권한과 익명성 정책은 백엔드/팀과 확정해야 하며 UI 숨김만으로 보호를 구현했다고 하지 않는다.
- GitHub CI는 제외한다. 로컬 검사와 필요한 브라우저 검증 결과를 PR에 기록한다.
- 향후 기능·버그 작업은 이슈부터 PR 제출까지 진행하고 사람은 리뷰·병합한다. 초기 설정 전달만 사용자가 파일·검증 결과를 확인한 후 커밋·푸시한다. 이 일회성 확인을 모든 작업의 승인 규칙으로 확대하지 않는다.
- 모델 기본값은 원본 초안의 Astra medium / Luna high를 유지한다. 계정 접근과 클라이언트 설정 적용은 별도로 검증한다.

## 2026-11-03 — 비단순 작업의 선행 planner

- 비단순 기능·동작 변경·버그 수정은 root가 별도 Astra medium planner에게 먼저 계획을 맡긴다. root 세션이 Astra여도 planner는 별도 역할로 실행한다.
- planner는 사용자 결과, 파일/API/mock 제약, UI 상태·접근성 위험, 소유권과 의존성이 명확한 구현 작업, 인수 기준·검사, 열린 질문을 root에 전달한다. root가 이를 검토하고 Luna 구현을 배정하며 최종 인수·통합·검사·Git 작업을 맡는다.
- 작은 문구·토큰·단일 요소 수정과 설명 요청은 root가 직접 처리한다. 사용자 지정 모델과 범위가 우선한다.
- planner 역할 호출이 지원되지 않으면 planner 지침과 Astra medium을 명시해 별도 하위 에이전트로 실행하고 이 경로를 보고한다. 명명된 역할과 명시적 Astra medium 실행이 모두 불가능하면 조용히 대체하지 않는다. 독립된 읽기 전용 탐색만 허용하고, 구현에 필요한 계획이 불가능하다는 제한을 알린 뒤 사용자에게 진행 방식 변경을 요청한다.
- planner·worker·tester·reviewer는 재귀적으로 역할을 시작하지 않고 전체 PR 절차도 반복하지 않는다. 동시 하위 에이전트 최대 2개 정책을 유지한다.
