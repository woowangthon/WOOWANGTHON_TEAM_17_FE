# Wayfind UI 검수

2026-11-10, 로컬 `design/wayfind-ui-review` 브랜치에서 FE #18을 기준으로 시작·여행 준비·개인 취향 화면을 재디자인했다. BE #15 및 AI #7은 기존 체크아웃을 유지한다. 병합·커밋·push·PR 제출은 하지 않았다.

## 디자인과 참고 자료

- [Hallmark](https://github.com/nutlope/hallmark)의 Wayfind를 적용했다. 안내판처럼 읽히는 구분선, 사각 입력·상태 선택, 명확한 행 정렬을 사용한다. 사용자가 지정한 한국어 Pretendard와 밝은 배경·연두색을 우선하므로 테마 기본 모노스페이스·파랑은 사용하지 않는다.
- [towards GDWEB 등록 자료](https://www.gdweb.co.kr/sub/view.asp?str_no=27171)의 검정·아이보리, 타이포 중심 방향과 [GDWEB](https://www.gdweb.co.kr/main/index.asp)을 참고했다. towards 직접 접속은 인증서 날짜 오류였고 보안 경고를 우회하지 않았다. GDWEB의 원본 이미지 주소도 브라우저에서 차단되어 직접 화면을 봤다고 주장하지 않는다.
- [Skunkworks](https://skunkworks.co.kr/)의 실제 로더 DOM은 검은 화면 위 단독 십자 표시였다. 이를 밝은 여행 화면의 십자/출발 표시로 새로 구성했다. 원본 코드나 이미지를 복제하지 않았다.
- 기존 충북 관광 사진 12장과 로컬 폰트, 제목 `충북 여행 계획`, 빈 헤더 라인, 우측 캡슐 생성 버튼을 재사용했다. 사진과 원본 출처는 기존 `trip-entry.md` 및 자산 LICENSE를 따른다.

## 화면 변경

- 시작: 큰 한국어 제목, 실제 장소 사진과 캡션·썸네일, 만들기/참여 폼의 정렬과 선택 표시를 일치시켰다. 모바일에서는 폼부터 사용한다.
- 여행 준비: 둥근 카드가 겹치는 구성을 구분선 중심의 조건 보드·준비 상태·예산으로 바꿨다. 방 이름을 제목으로 표시하고 긴 이름은 줄바꿈한다.
- 개인 취향: 원문과 정리한 조건을 나란히 배치하고 실제 순서를 목록으로 표시한다. 중요도·걷기 선택·확인 동작과 기존 안내를 유지한다.
- 공통: 색·글꼴·간격을 토큰으로 정리했다. 텍스트 크기는 `--text-size-…`, 글꼴은 `--font-body`로 구분한다. 레거시 미리보기 CSS는 기존 색을 토큰으로 옮기고 간격·모서리·공통 조작 스타일을 맞췄다.

주요 문구 변경은 `01 PREPARE` → 실제 방 이름, `02 PERSONAL PREFERENCES` → `내 취향과 제약`, 장식 점·화살표·가운데점 구분 → 텍스트 상태와 개별 메타 항목이다. 개인정보 안내와 개인 입력의 임시 보관·AI 미연결·일정 미연결 의미는 유지한다. 실제 원문·날짜·가격·참여자 수를 새로 만들어 제품 실적으로 사용하지 않는다.

## 로딩과 기능 경계

- 사진 로딩 표시는 최초 선택 사진을 불러오는 동안 사진 영역 안에만 나온다. 폼을 가리지 않고 load/error/이미 캐시된 경우 즉시 종료한다.
- 여행방 로딩은 재접속·최초 준비 데이터 조회의 기존 상태만 사용한다. 공통 조건 주기 갱신·저장·충돌 비교에는 전체 로더를 띄우지 않는다.
- 가짜 퍼센트·의도적인 대기 시간·자동 AI 완료 연출이 없다. 모션 감소에서는 정지한다. JavaScript 없이도 시작 페이지 사진·본문과 기능 안내를 볼 수 있고, 방 화면에는 시작 링크가 있는 대체 안내가 있다.
- 방 생성·참여·재접속, OWNER 수정 권한, 저장 버전 충돌과 초안 보존, pending 잠금, 접근권한 상실 시 정보 숨김은 그대로다. 개인 입력과 개인 확인은 여전히 메모리 초안이며, 이번 작업은 AI/개인 저장/생성 API를 연결하지 않는다.

## 검수

- `npm run check`: TypeScript·oxlint·Vite 빌드 통과. `npm test`: 26개 통과. 테스트 파일 변경 없음.
- 실제 브라우저: 만들기/참여 탭 전환과 입력 복원, 사진 넘김·일시정지, 실제 방 생성, 공통 조건 저장·새로고침 복원, 개인 수동 입력·로컬 확인, 새로고침 시 개인 입력 초기화 확인.
- 모바일: 390px 개인 화면과 조건/원문 수정창의 입력·버튼 확인. Escape로 수정창을 닫으면 수정 버튼으로 초점이 돌아옴.
- 긴 이름: 40자 방 이름과 20자 닉네임을 실제 로컬 방에 넣어 375px·1024px에서 줄바꿈 확인. 두 독립 검토 지적 모두 수정·재캡처 후 해소 판정.
- Hallmark 검사와 전후 비교는 로컬 `.hallmark`에 기록한다. 기존 링크 1/1, 입력 2/2, 핸들러 33/33 보존 검사 통과. 실제 화면 캡처는 1280·1440·1920 및 375/390px에서 수행했다.
- 시작·준비 화면을 함께 검사한 최종 결과는 Floor 실패 0, 미해결 Reflex 0, 경고 0이다. 보조 버튼/숫자 없는 spinner/기존 글꼴 굵기 구분에 대한 Finish 항목 3개는 근거를 기록했다. 독립 검토의 최종 판정은 `ship`이며 헤더와 닉네임 줄바꿈 지적 2개가 모두 해소됐다.
- 모션 감소와 JavaScript 비활성 대체 안내는 코드 검토로 확인했다. 다른 OS/모든 브라우저 조합의 검수를 완료했다고 주장하지 않는다.
- 계획·독립 검토: 별도 GPT-6.1 Sol high. 제한된 구현 작업: Luna high 2명. root가 통합·실제 브라우저 검사·빌드·디자인 검사를 수행했다.

검수 주소는 `http://localhost:8020/`, 예시 방은 `http://localhost:8020/room.html?preview=room`이다. 실제 생성·저장 검사는 검수 전용 로컬 DB만 사용했다. 공용 DB의 데이터·스키마와 키 설정은 변경하지 않았다.
