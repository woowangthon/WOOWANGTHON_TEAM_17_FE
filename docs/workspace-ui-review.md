# 여행방 워크스페이스 검수

후속 여행 준비 수정과 최신 검증은 [여행 준비 입력 정리](preparation-ui-refinement.md)를 따른다. 아래 `8020` 검수 서버·36개 테스트·실제 AI 검증은 이전 작업의 기록이다. 최신 FE는 빌드 완료했으며 사용자가 기존 BE `run.py`로 실행해 `http://127.0.0.1:8017`에서 확인한다. 이번 후속 수정에서는 서버를 시작하거나 실제 AI·공용 DB 요청을 실행하지 않았다.

이번 변경은 로컬 검수용이다. 기존 시작 화면과 방 진입, 공통 조건·권한 API를 유지하면서 여행방을 중앙 입력 작업 영역과 자유 캔버스로 재구성한다. 커밋·push·PR·공용 DB 변경은 포함하지 않는다. 사용자 지시에 따라 PR을 만들기 전에 제목과 본문을 대화창에서 검수받는다. AI 경로 추천·계산은 이번 필수 완료 기준에서 제외한다.

## 화면 기준

- 밝은 배경, 로컬 Pretendard, 절제된 연두 포인트와 얇은 구분선.
- 여행 준비와 내 취향을 중앙에서 충분한 크기로 작성한다. 접이식 탐색은 입력의 유일한 진입점으로 사용하지 않는다.
- 공통 조건은 OWNER만 수정한다. 버전 충돌 때 입력을 보존하고 명시적으로 최신 기준을 적용한다.
- 캔버스는 자유로운 카드 위치와 연결선으로 정한 방문 순서를 분리한다. 카드·연결 삭제 뒤 자동으로 다른 카드를 연결하지 않는다.
- 장소 탐색 패널은 여닫을 수 있다. 아직 구현되지 않은 검색·AI 추천을 실제 서버 결과처럼 표시하지 않는다.

## 실제 연결과 미리보기

| 기능 | 이번 연결 범위 |
| --- | --- |
| 방 진입·참여자·공통 조건 | 기존 BE·기기 쿠키·준비 상태와 OWNER 저장 재사용 |
| 개인 조건 | 본인 조회·저장, 저장된 원문의 AI 해석과 해석값 저장 |
| 최종 확정 | 기존 BE의 직접 검토 정책 유지. AI 분석이 자동으로 `reviewed:true`를 전송하지 않음 |
| 캔버스 | 이 기기의 비개인 화면 검수 데이터. 공유 DB 일정·실시간 공동 편집과 구분 |
| 일정 생성·경로 계산 | 진행 중인 팀의 생성·경로 API에 후속 연결. 샘플을 실제 생성 결과로 표시하지 않음 |

개인 데이터는 브라우저 영구 저장소에 보관하지 않는다. 원문·취향은 본인 API에서만 조회한다. 분석 뒤 최종 PUT이 성공한 경우에만 분석·저장 완료로 표시한다. 새로고침은 서버의 마지막 저장본을 복원한다.

## 실행과 검수

FE 빌드 후 기존 BE 검수 서버에서 제공한다. 현재 로컬 서버는 `http://localhost:8020`이며 [준비 화면 예시](http://localhost:8020/room.html?preview=room)와 [캔버스 예시](http://localhost:8020/room.html?preview=room&view=canvas)를 분리해서 볼 수 있다. 예시 준비 입력은 서버로 보내지 않는다. 일반 방의 입력은 기존 인증 API를 사용한다.

검수 서버는 공용 `chungbuk_trip1`이 아니라 기존 loopback 검수 DB `127.0.0.1:3317/osami_pr_review`를 사용했다. 공용 DB migration·초기화·데이터 변경은 하지 않았다. BE·AI 소스도 이번 화면 변경에서 수정하지 않았다.

2026-11-10 실제 검증:

- `npm run check`: TypeScript·lint·production build 통과. lint 경고 없음.
- `npm test`: 36개 통과. 개인 응답/버전/멱등 헤더, 연결 그래프의 분기·순환·날짜 경계, 저장본 검증과 임의 속성 제거 포함.
- 디자인 검사: 두 화면 실제 렌더링, 0 FAIL / 0 REFLEX / 0 WARN, Finish 3개 답변 기록. 캡처와 결과는 `.hallmark/workspace-design-check.txt` 및 `.hallmark/workspace-shots`에 있다.
- 실제 BE·검수 MySQL: OWNER 공통 조건 저장, 개인 저장 후 새로고침 복원, Gemini 실제 원문 해석과 최종 PUT 저장 성공. 분석만으로 기존 직접 확정을 위조하지 않음을 확인했다.
- 실패 검수: 브라우저에서 PUT 응답 유실 및 후속 GET 실패를 주입해 미저장 원문 유지 확인. 모의 AI 503 이후에도 입력 수정·일반 저장 가능. 공통 조건 409에서 편집 입력 유지.
- 별도 브라우저 세션의 일반 참여자는 공통 조건 수정 불가, 방장 개인 취향 조회 불가. 공개 준비 응답에 개인 원문·해석값 없음.
- 캔버스: 드래그가 연결 순서를 바꾸지 않음, 이동 실행 취소/다시 실행, 연결 해제 후 두 카드 유지, 메뉴로 연결, 장소 삭제/교체/날짜 이동, 직접 후보 추가·검색/종류 필터·새로고침 복원 확인.
- 날짜별 선택 경계를 검수했다. 1일차 연결 선택 후 2일차로 전환해서 Delete를 눌러도 보이지 않는 1일차 연결을 지우지 않는다.
- 1440/1024/390px 준비 화면과 fresh mobile 진입 확인. 휴대폰은 탐색·장소 패널이 기본으로 닫혀 있고 열기·Escape 닫기가 가능하다. 초대 코드 복사도 모바일 헤더에서 제공한다.
- `git diff --check` 통과. GitHub 이슈·커밋·push·PR은 만들지 않았다.

별도 GPT-6.1 Sol high 설계와 독립 검토를 수행했다. 검토에서 지적한 실패한 재조회 시 원문 손실, 취소된 작업의 상태 복구, 숨겨진 날짜 연결 삭제를 수정하고 검수했다. Luna high 구현 작업의 일부는 실행 한도에 도달했으며 root가 남은 캔버스 통합·수정·검증을 직접 마쳤다.

## 남은 연결 범위

현재 캔버스는 비개인 로컬 예시를 저장한다. 공용 일정 저장·참여자 실시간 편집·DB 장소 목록·AI 일정 생성과 경로 계산은 연결되지 않았다. 준비·취향의 실제 서버 저장과 혼동하지 않는다. AI 경로는 사용자 요청대로 이번 필수 범위가 아니다. 기존 BE의 `confirmed`는 직접 검토 확정을 뜻하므로 분석 결과 자동 저장만으로 전원 확정 상태나 생성 가능 상태를 만들지 않는다.
