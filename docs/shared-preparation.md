# 공통 여행 조건과 전체 준비 상태 연결

사용자 요청 범위는 여행 준비 화면의 공통 조건 공유와 전체 참여자의 준비 상태 표시다. 개인 원문 저장·AI 해석·개인 조건 확정의 서버 연결은 이번 범위에 포함하지 않는다. 기존 항목별 미정 안내와 옅은 표시, 예산의 `예산을 설정해 주세요`를 유지한다.

## 서버 기준 데이터

- 기존 방 재접속 후 `GET /api/v1/trips/{tripId}/preparation`으로 공통 조건·현재 버전·수정 권한·ACTIVE 참여자와 준비 상태를 읽는다.
- 사이드바와 준비 상태 카드는 같은 서버 `members`를 사용한다. `writing`은 작성중, `confirmed`는 확정 완료로 표시한다. 본인은 서버 member ID로 구분한다.
- 예정 인원과 실제 ACTIVE 인원은 구분한다. 개인 화면의 로컬 확정은 서버 참여자의 준비 상태를 바꾸지 않는다. 개인 원문·정리 조건·음식·걷기 답변을 공동 화면에 표시하지 않는다.
- 일정 생성 준비 사유는 서버 readiness를 따르지만 실제 생성 기능이 없으므로 생성 버튼은 활성화하지 않는다.
- 미리보기 `?preview=room`은 기존 예시·로컬 편집 모드이며 서버 요청을 하지 않는다.

## 공통 조건 편집

서버가 수정 가능으로 반환한 OWNER만 `PUT /api/v1/trips/{tripId}/conditions`로 저장한다. 문자열 숫자는 정수 또는 null, 빈 텍스트·미정 교통은 null로 변환한다. 자유 입력을 지역 코드·좌표·시간·숙박 boolean 등으로 추정하지 않는다.

편집 시작 시 조건 버전을 고정하고 배경 갱신으로 입력을 덮어쓰지 않는다. 버전 충돌에서는 입력을 보존하고 최신 조건을 조회한 뒤 명시적으로 재적용할 수 있게 한다. 응답 유실·네트워크 실패를 자동 PUT 재전송으로 처리하지 않는다. 저장 중 중복 제출·모달 종료를 막고, 필드 오류는 해당 입력에 연결한다. 성공한 공통 저장은 서버에서 전원 재확인을 요구하므로 준비 상태를 다시 읽는다. 저장 후 상태 조회 실패는 저장 실패와 구분한다.

보이는 탭의 주기적 갱신·창 복귀·사용자 새로고침으로 다른 참여자의 변경을 반영한다. 요청 중복과 늦은 GET이 새 저장값을 되돌리지 않게 하고, 인증·접근 권한을 잃으면 공동 정보를 숨기고 안내한다.

## 계약과 후속 범위

원본은 [여행 준비·개인 조건](https://app.notion.com/p/412e977e49088197b345d73603c6a27f)과 [공통 규칙](https://app.notion.com/p/40ee977e49088189b512e6e817984d48)이다. [BE #11](https://github.com/woowangthon/WOOWANGTHON_TEAM_17_BE/pull/11)의 구현을 재사용하며 신규 endpoint나 DTO를 추가하지 않는다. [FE #17](https://github.com/woowangthon/WOOWANGTHON_TEAM_17_FE/issues/17)의 일부 범위만 연결하므로 이슈 전체를 완료 처리하지 않는다.

개인 원문·정리 조건의 영속 저장, AI 제안 요청·검토·반영, 서버 직접 확정은 별도 후속 FE 작업이다. 일반 모드에서 개인 화면의 초안 확인을 서버 확정처럼 표시하지 않는다. 서버 migration 002가 실행 환경에 준비되어야 하며 이 FE 작업에서 공용 DB에 적용하지 않는다.

## 수동 확인

1. 격리 BE·DB에서 방장 브라우저로 방을 만들고 독립된 참여자 브라우저로 같은 초대 코드에 참여한다.
2. 미정 조건이 항목별 안내로 보이는지, 두 화면의 참여자 목록·준비 상태가 같은지 확인한다.
3. 방장이 공통 조건을 수정하고 회원 화면에서 자동/명시적 갱신으로 같은 값을 확인한다. 회원은 수정할 수 없어야 한다.
4. 편집 도중 다른 방장 탭에서 먼저 저장한다. 이전 편집 입력을 유지한 409 안내와 최신 조건 확인·명시적 재적용을 확인한다.
5. 검수 준비 단계에서 서버에 확정된 참여자를 만들고, 공통 수정 뒤 전원 작성중으로 바뀌는지 확인한다. 이 준비 단계는 개인 FE 연결 완료를 의미하지 않는다.
6. 네트워크 실패·재시도·탭 숨김/복귀·새로고침·주소 누락, 데스크톱·390px·키보드·모달 동작을 확인한다.

검수용 데이터를 공용 DB에 만들거나 초기화하지 않는다. 실제 서버 검증과 API 모의 응답 검증을 구분해 PR에 기록한다.

## 검증 결과와 실행 환경

- `npm run check`의 타입·lint·빌드 통과, `npm test` 26개 통과. API 6개 검사는 요청 경로·쿠키 옵션·정수/null 변환·DTO·권한/버전/필드 오류·취소를 확인한다.
- 실제 FE API 모듈을 격리 BE 8018과 `127.0.0.1:3317/osami_entry_test`에 연결해 두 세션의 조건 공유, OWNER 전용 저장, 409 데이터 보존, 서버 필드 오류, 공개 확정 상태, 원문 비노출, 공통 변경 후 전원 작성중, 개인 초안 보존의 8개 항목을 확인했다.
- 독립된 IAB 방장·Chrome 회원으로 생성/참여했다. 실제 3명 목록과 본인 표시, 회원 읽기 전용, 기존 항목별 미정 문구, 방장 저장 후 회원 자동 갱신, 확정 회원의 작성중 전환을 확인했다.
- IAB 방장 탭 두 개에서 실제 409를 발생시켜 입력 유지·서버/내 입력 비교·최신 조건 명시 확인 후 재적용을 확인했다. 서버가 거부한 지역 제어문자 입력의 필드 오류 표시와 포커스도 확인했다. 새 방장 탭 재접속으로 서버 조건 버전 3 복원을 확인했다.
- 최종 1440px/390px 화면 크기·캡처 검수는 브라우저 도구의 CDP/viewport 응답 시간 초과로 끝내지 못했다. 임시 viewport 초기화도 시도했지만 같은 도구 오류가 발생했다. 필수 최종 UI 검수 미완료로 PR은 Draft다. 빌드 통과를 이 검수의 대체로 기록하지 않는다.
- 기존 BE 설정을 사용한 **테이블 존재 여부만의 읽기 전용 확인**에서 준비 테이블은 0개였다. 공용 DB에 migration을 적용하지 않았으므로 실제 일반 실행에는 BE 적용 담당자의 migration 002 준비가 필요하다. 검수 DB의 3개 테이블과 구분한다.
- 독립 Sol high 검토에서 저장 경로, 서버 필드 오류 연결, 접근권한 상실 시 숨김, 저장 중 입력 잠금, 저장 후 상태 무효화·늦은 응답·명시적 충돌 처리의 지적을 수정·재검토했다. 최종 P1/P2는 없다.
- 실행 역할: GPT-6.1 Sol high planner·reviewer, GPT-6 Luna high API/UI worker 두 명. root가 사용자 문구 별도 커밋 보존·통합·실제 서버/브라우저 검수·최종 명령 검증·GitHub 전달을 수행했다.
