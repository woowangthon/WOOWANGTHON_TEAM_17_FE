# 여행 준비 버튼 통일과 FE 체크포인트

2026-11-10 사용자 요청에 따른 FE 변경이다. BE·AI 변경, 서버·브라우저 실행, 실제 API·DB 호출, push·PR은 포함하지 않는다. 최종 화면은 사용자가 기존 BE `run.py`로 검수한다.

## 동작을 구분하는 두 버튼 계열

조건 저장·취향 분석·취향 저장·준비 완료·일정 만들기는 동일한 로컬 `PreparationActionButton`을 사용한다. 투명한 바탕, 글자와 얇은 밑선, 분리된 작은 정사각 화살표 영역으로 구성한다. 동일한 높이·여백·글꼴·초점·로딩·비활성 규칙을 사용한다. 기존 연두색 둥근 박스와 취향 분석 전용 스타일을 제거한다. 요청 중에는 같은 아이콘 영역에 진행 표시를 두고 중복 클릭을 막는다.

이동수단은 원형 라디오 표시 대신 실제 버튼으로 선택한다. 기존 다섯 값과 단일 선택 의미는 유지한다. 선택값은 `aria-pressed`로 제공하고 native button의 키보드 조작과 fieldset 비활성화를 사용한다. 작업을 실행하는 버튼과 값을 고르는 버튼을 같은 의미로 섞지 않는다.

## 참고 확인 범위

- [SORO Work](https://soroweb.co.kr/v6/work/): 페이지와 실제 CSS를 조회했다. 간결한 글자 중심 조작과 중립 배경/짙은 선택 상태를 참고했다. 원본 CSS를 그대로 복제하지 않는다.
- [GDWEB 선정작 목록](https://www.gdweb.co.kr/sub/list.asp?Txt_bcode1=): 현재 목록을 조회해 참고 범위를 확인했다.
- [Towards](https://towards.co.kr/): 웹 조회는 timeout, 직접 문서 조회는 연결 오류였다. 이번에 화면을 새로 확인했다고 주장하지 않으며 기존 시작 화면에 적용한 방향을 유지한다.
- 로컬 조회 자료는 `.hallmark/button-references/`에만 보관하며 FE 커밋에 포함하지 않는다.

## 지역 복수 선택과 파싱 연결

지역 복수 선택은 다음 BE 논의 대상으로 남긴다. 현재 `Conditions.region`은 문자열 하나다. 이번 UI 커밋에서 여러 지역을 문자열에 임의로 합치거나 저장되는 것처럼 표시하지 않는다. 후속 규격은 전체 선택과 개별 선택의 배타성, 선택 목록과 요약, 기존 단일 지역 호환을 함께 정한다.

현재 FE는 공통 BE의 개인 해석 API를 호출한다. `app/preparation.py`의 기본 해석기는 AI 저장소의 `chungbuk_trip_ai.interpret_personal_draft`를 사용한다. BE의 해당 구현은 박정환 작성 `179f2b6`에서 추가됐고 현재 BE `main`의 `d823f0e`에도 유지된다. 설치된 AI 패키지는 `0.4.0`이며 인접 AI 저장소를 editable로 참조한다. 이번 FE 작업은 해석기·모델·DB 저장 방식을 교체하지 않는다.

## 커밋 범위와 검증

이전 대화에서 누적한 FE의 시작 화면·여행 준비·개인 API 연결·로컬 캔버스 시안과 이번 버튼 변경을 FE 작업 브랜치의 체크포인트로 보존한다. BE·AI 파일, 환경 설정과 비밀값, 임시 실행 코드, 참고 사이트 원문·로컬 캡처는 제외한다. 캔버스의 공동 DB 저장·실시간 편집은 여전히 미연결이다.

타입·lint·production build와 Node 단위 검사 48개가 통과했다. 별도 소스 검토에서 찾은 줄바꿈 후 동작 버튼의 왼쪽 정렬 문제를 수정했다. 브라우저 없는 정적 스타일 검사를 수행했다. 최종 브라우저·서버 검수는 사용자 지시에 따라 실행하지 않으며 시각적 검수 완료를 주장하지 않는다. PR은 제목·본문 검수 지시가 유지되므로 만들지 않는다.
