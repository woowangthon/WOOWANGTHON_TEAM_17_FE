# 여행 준비 상태와 최종 로컬 검수

2026-11-10 후속 수정이다. 이 문서를 앞선 여행 준비 시안·검수 기록보다 우선한다. 최종 사용자 지시에 따라 서버 시작·재시작·브라우저 실행·화면 검수·DB 검사는 수행하지 않는다. 사용자가 BE `run.py`로 실행해 최종 화면을 검수한다. 커밋·push·PR도 보류한다.

## 상태와 실제 준비 완료

이전 화면은 본인에게 개인 저장 상태, 다른 참여자에게 공용 확인 상태를 표시해 같은 사람의 상태가 두 화면에서 달랐다. 또한 FE에 직접 확정 요청이 없어 저장만으로 공개 준비 완료에 도달할 수 없었다.

모든 참여자는 공용 준비 응답의 동일한 값을 사용한다. `writing`은 `준비 중`, `confirmed`는 `준비 완료`다. 저장·미저장 상태는 본인 입력 영역에서만 표시한다. 저장한 여행 조건·취향을 확인하는 체크와 `준비 완료` 버튼으로 기존 API를 명시적으로 호출한다. AI 분석·초안 저장·체크 선택만으로 확정하지 않는다.

- 원본: [여행 준비·개인 조건](https://app.notion.com/p/412e977e49088197b345d73603c6a27f).
- 기존 `POST /api/v1/trips/{tripId}/preferences/me/confirm` 재사용.
- 요청은 현재 `expectedConditionsVersion`, `expectedPreferenceVersion`, `reviewed:true`만 포함한다.
- 저장된 원문·좋아하는 것·걷기 값과 미저장 변경 없음이 필요하다. 공통 조건을 편집 중이거나 버전이 다르면 확정하지 않는다.
- 개인·공통 입력 수정, 저장·분석·재조회, 버전 변경은 검토 체크를 해제한다. 중복 클릭·취소된 요청·늦은 응답을 차단한다.
- 확정 응답의 상태와 두 버전을 엄격히 확인한다. 불확실한 응답은 성공으로 표시하지 않는다.
- 개인 저장·확정 이후 이전 공용 GET을 무효화하고 서버에서 준비 상태를 다시 읽는다. 일반 갱신은 기존 10초 간격 및 창 복귀 방식을 유지한다.
- 공통 조건 저장은 서버의 전원 재확인 정책을 따른다. 원문·취향 입력은 유지한다.
- 일반 저장 검증 실패·AI 실패·준비 완료 실패도 입력 영역에 오류를 한 번 표시한다. 공용 상태의 조용한 갱신 실패는 참여자 영역에서 재시도할 수 있다.

## 화면 정리

`정리한 취향`을 `내 취향`으로 통일한다. `나만 보기` 표시는 제거하며 실제 개인 정보 접근 제한은 유지한다. 참여자는 제목 가까이에 간결하게 모으고 긴 전체 테두리 줄과 별도 상태 알약을 제거한다. 이동수단은 자가용·대중교통·전세버스·도보·미정의 네이티브 라디오 선택이다. 공통 `.field label` 규칙이 선택 항목의 정렬을 덮던 원인을 제거한다. 기존 충북 전체·11개 시군 사진 카드와 취향 입력 유지 동작은 보존한다.

[Linear 프로젝트 화면](https://linear.app/docs/projects)과 [Notion 공동 작업 안내](https://www.notion.com/help/collaborate-within-a-workspace)의 간결한 멤버 배치와 정보 계층을 참고했다. 공식 문서와 공개 페이지를 확인했으며, 우리 화면에 실시간 접속·커서 기능이 구현됐다는 의미는 아니다. 참고 캡처는 사용자 실행 제한 이전에 저장한 `.hallmark/preparation-collab-references/`에 있다.

## 새 BE 병합본 유지

BE 작업 폴더는 변경 없는 상태에서 `main`으로 전환하고 `origin/main`의 `d823f0e`(PR #17 병합)로 fast-forward했다. 새 일정 생성·후보 검증·경로 처리·저장·migration 파일을 원본 그대로 유지했다. BE 소스를 우리 시안으로 덮어쓰지 않았다. 기존 준비 API·실행 파일·의존성 선언은 이전 검수 기준 `1278a29`와 동일하다. 새 생성 API를 FE 일정 생성 버튼에 연결하는 일은 이 수정에 포함하지 않는다.

공용 DB migration이나 데이터 변경은 하지 않았다. 선택적 Kakao 설정을 포함한 병합본의 환경 규칙을 유지한다. 실행 없이 Python 문법 컴파일과 설치 의존성 검사만 수행했다.

## 검증 구분과 실행

최종 수정본의 타입·lint·production build와 Node 단위 검사 48개가 통과했다. 브라우저 없는 정적 디자인 검사를 수행했다. BE는 Python 문법 컴파일·`pip check`가 통과했으며 `main`이 `origin/main`과 동일한 `d823f0e`이고 작업 폴더에 수정이 없음을 확인했다. 최종 화면의 동작·배치는 사용자 요청에 따라 여기서 실행 검수하지 않는다.

그보다 앞선 상태에서는 두 독립 모의 브라우저의 공개 상태 일치, 직접 확정·중복 클릭, 공통 조건 수정 후 전원 초기화, 지연 GET 무효화, 개인 저장 후 본인 초기화, 갱신 실패 표시, 409·응답 유실 복구, 이동수단 값·키보드 동작 등 10개 시나리오를 확인했다. 이는 최종 참여자·이동수단 재배치와 후속 오류 안내 수정 이전의 기록이며 최종 UI 통과 증거로 사용하지 않는다. 공용 DB·실제 AI 요청을 사용한 검수도 아니다.

사용자는 PyCharm의 기존 BE `run.py` 구성을 실행하고 `http://127.0.0.1:8017`에서 확인한다. 이미 실행 중인 이전 프로세스는 사용자가 종료 후 다시 실행해야 새 BE 코드가 적용된다. 이 작업에서 기존 프로세스를 종료하거나 재시작하지 않는다.

## 2026-11-11 참여자·초대 코드 후속 UI

여행 제목 왼쪽 아래에 저장된 날짜·지역 요약을 두고, 참여자 수 버튼은 오른쪽의 접이식 준비 상태 목록을 연다. 목록은 공개 `writing`/`confirmed` 값과 기존 본인 표시를 그대로 사용하며, 조건 입력 위치를 밀지 않는다. 외부 클릭·Escape·캔버스 이동·방 변경·접근 권한 상실 시 닫히고, 공개 상태 갱신 중에는 열린 목록을 유지한다. 초대 코드 복사 피드백은 버튼 옆에서 성공 2.5초, 수동 복사 안내 5초 동안만 보인다.

이 후속 수정은 `RoomPage.tsx`와 `preparation.css`의 로컬 UI 변경이다. 서버·브라우저·DB를 실행하지 않으며, 이 문서의 앞선 검수 범위와 API 동작은 바꾸지 않는다.
