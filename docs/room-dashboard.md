# 여행방 준비 화면

방 생성·초대 참여가 성공하면 기존과 같이 `/room.html?tripId=...`로 이동한다. 이 페이지는 기존의 연결 확인 화면을 여행 준비와 내 취향·제약의 두 화면으로 확장한다. 사용자가 제공한 와이어프레임의 정보 구조를 따르되, 시작 화면의 밝은 배경·짙은 제목·연두색 포인트·Pretendard를 이어 사용한다. 시작 화면의 사진·입력 폼·생성 및 참여 요청은 유지한다.

## 실제 정보와 초안

- 방 이름·초대 코드·본인 닉네임과 방장/참여자 역할은 기존 `POST /api/v1/trips/{tripId}/reconnect`의 응답을 사용한다. 새 방이나 세션을 만들지 않는다.
- 초대 코드를 복사할 수 있다. 클립보드를 사용할 수 없으면 화면의 코드를 직접 선택해 복사한다.
- 공통 여행 조건과 내 취향·제약은 **이 화면의 초안**이다. 페이지 메모리에서만 유지하고 새로고침하면 사라진다. 서버 저장·다른 참여자와 공유·일정 생성에는 사용하지 않는다.
- 예정 인원은 사용자가 계획하는 인원이며 현재 참여자 수가 아니다. 현재 계약에는 전체 참여자 조회가 없어 실제 본인 정보만 표시한다.
- 개인 원문과 정리한 조건은 내 취향·제약 화면에만 표시한다. 네트워크·URL·localStorage·sessionStorage·로그에 보내거나 남기지 않는다. 여행 준비 화면에는 본인의 준비 상태만 표시한다. ACTIVE 회원을 취향 확정 완료로 해석하지 않는다.
- 원문·정리한 조건·추가 답변이나 공통 초안이 바뀌면 본인 확인 상태를 해제하고 재확인을 안내한다. 확인 체크와 본인의 직접 확정은 이 화면 내 상태이며 서버 확정이 아니다.
- AI 요청은 실행하지 않는다. 실제 방에서는 직접 조건을 정리하며, AI 해석처럼 보이는 예시 내용은 미리보기에서만 사용한다. 일정·변경 이력은 아직 제공하지 않는다.

## 화면 구조

공통 헤더에는 방 이름과 기간·인원·지역 요약, 초대 코드와 본인 정보를 둔다. 사이드 메뉴는 여행 준비와 내 취향·제약을 연결한다. 여행 준비에는 다음 행동, 기본 조건, 전체 예산, 준비 상태와 일정 생성 전 확인 사항을 표시한다. 내 취향·제약은 원문과 정리한 조건을 나란히 놓고 중요도·걷기 답변·확인·확정 흐름을 제공한다. 모바일에서는 메뉴와 두 열을 세로로 배치한다.

`/room.html?preview=room`은 실제 방이나 서버 없이 두 화면을 검수하는 전용 미리보기다. 예시 조건·참여자는 이 모드에서만 사용하며 실제 정보처럼 표시하지 않는다.

기존 [여행방 시작 계약](https://app.notion.com/p/40ee977e49088105a9b4ce4df0aef6f8)과 [공통 규칙](https://app.notion.com/p/40ee977e49088189b512e6e817984d48)을 재사용하며 새 API나 기존 DTO 변경은 없다. 공동 조건 저장·전체 참여자 조회·개인 조건 확정은 별도 계약과 BE 구현 이후 연결할 후속 범위다.

## 수동 검수

1. BE와 FE를 실행하고 시작 화면에서 여행방을 생성하거나 코드로 참여한다.
2. 방 이름·본인·역할·초대 코드가 서버 응답과 같은지 확인하고 코드를 복사한다.
3. 조건 편집에서 날짜 역전과 잘못된 인원·예산을 입력한다. 오류 안내와 입력 유지, 취소·Escape·열었던 버튼으로 포커스 복귀를 확인한다. 취소하면 반영 전 요약값을 유지해야 한다.
4. 초안을 반영한 뒤 변경 내용과 초안 안내를 확인한다. 새로고침하면 초안이 초기화되고 실제 방 정보는 재접속으로 다시 표시되어야 한다.
5. `tripId`가 없거나 접근할 수 없는 방이면 복귀 안내를 확인한다. 네트워크 오류의 재시도가 방을 새로 만들지 않아야 한다.
6. 데스크톱과 390px 화면에서 긴 방 이름·닉네임 줄바꿈, 키보드 조작, 가로 넘침 여부를 확인한다. 기존 `/?preview=ui`도 확인한다.
7. 내 조건 확인하기로 이동해 원문·정리·중요도·추가 답변을 수정하고 직접 확정한다. 돌아오면 본인 상태만 바뀌고 원문은 공동 화면에 보이지 않아야 한다. 원문·정리·공통 초안 수정 시 재확인 상태로 되돌아가는지 확인한다.

실제 서버 검수는 격리 테스트 환경에서 진행하며 자동 테스트용 방을 공용 DB에 생성하지 않는다. 모의 응답을 사용한 브라우저 검증은 실제 서버·DB 검증과 구분한다.

## 이번 변경의 검증

- 타입·lint·빌드: `npm run check` 통과.
- 기능 검사: `npm test` 20개 통과. 새 검사에는 방 응답의 역할·필수값, 미정 조건의 준비 상태, 날짜·숫자 경계와 개인 조건 입력 여부가 포함된다.
- Chrome 1440×1000 및 390×844에서 두 화면 배치, 입력과 확정, 중요도 수정 뒤 확정 해제, 공통 조건 변경 뒤 재확인, 원문 편집 취소·Escape·포커스 복귀, 날짜 역전·인원 오류 안내와 입력 유지, 개인 화면의 코드 복사 성공 안내를 확인했다.
- 새로고침으로 초안이 초기화됨과 기존 `/`·`/?preview=ui` 경로도 확인했다. `tripId` 누락 시 복귀 안내를 제공한다.
- 독립 Sol high 검토의 미정 조건 완료 표시와 개인 화면 코드 복사 안내 누락을 수정하고 재검토했다.
- 브라우저 검수는 `preview=room` 예시 모드다. 실제 BE·DB의 방 생성→새 화면 진입은 이번 작업에서 재실행하지 않았다. 클립보드 권한 거부를 강제하는 브라우저 검수는 하지 않았고 실패 시 직접 복사 수단은 코드로 검토했다.
- 실제 실행: 별도 GPT-6.1 Sol high planner·reviewer, GPT-6 Luna high 구현·스타일 worker 두 명. root가 통합과 최종 검증을 수행했다.
