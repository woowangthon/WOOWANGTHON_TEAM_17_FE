## 공통 카드·상태

- 조건 카드: 항목명·값·공유 조건 설명, 선택적 수정 동작과 재확인 안내. 개인 원문은 표시하지 않는다.
- 여행방 참여자 상태: 본인·다른 참여자 모두 공개 API의 writing은 **준비 중**, confirmed는 **준비 완료**로 표시한다. 본인의 저장·미저장 상태는 개인 입력 영역에서만 표시한다. 저장한 여행 조건과 취향을 직접 확인한 뒤 준비 완료를 요청하며, 초안 저장·AI 분석이 자동 확정하지 않는다. 세부 기준과 사용자 실행 범위는 [여행 준비 상태와 최종 로컬 검수](preparation-confirmation-review.md)를 따른다.
- 일정 카드: 시작·종료 시간, 제목, 기간·분류, 선택 상태, 다음 이동 설명을 표시한다. 실제 버튼으로 선택하고 연결된 상세와 같은 선택값을 공유한다. 첨부 시안의 정보 구조를 참고하며 기존 연두색 테마를 유지한다.
- 상태 UI: 로딩·빈 결과·오류·재시도를 구분한다. 실패 시 입력을 보존하고, 진행 중 버튼 비활성화와 요청 로직의 동기 잠금을 함께 사용한다.
- 확인창: 기본 안내 종료와 실제 확인 콜백을 구분한다. 처리 중 중복 확인·종료를 막고 종료 후 원래 조작 요소로 초점을 돌린다.
- 긴 이름·제목은 줄바꿈하고, 모바일에서는 일정 상세를 목록 아래로 배치한다. 색만으로 상태를 전달하지 않는다.

미리보기의 조건 수정·참여 확정·입력 처리·재시도는 로컬 예시이며 실제 서버 저장이나 권한 검증을 수행하지 않는다.

|화면|중요한 동작|
|---|---|
|방 진입|생성·코드 참여·기존 참여 재접속|
|여행 준비|내 다음 행동·참여 상태·생성 불가 사유|
|개인 조건|원문과 해석 비교·수정·직접 확정|
|일정|목록·지도·선택 상세 동기화|
|수정·복원|비교·재검사·확인·새 버전 저장|

공통 조건 변경 시 재확인이 필요하다. 개인 원문은 공동 화면에서 숨긴다. 예산은 전체 총액과 추정값을 구분한다. UI의 비활성만으로 권한·저장 가능 여부를 판단하지 않는다.

## 여행 종합 본문

`여행 종합`(`view=itinerary`)은 공동 캔버스의 현재 편집 내용을 **전체 여행을 최종 점검하는 화면**으로 보여준다. 최신 표시 기준과 실제 검수 결과는 [캔버스 편집 일정 보기](canvas-itinerary.md)의 마지막 `최종 점검을 위한 전체 여행 종합` 절을 따른다. 이전의 행 안 상세 펼침 시안은 현재 기준이 아니다.

사용자가 전체 일정·큰 지도·독립 상세 영역의 현재 구성을 긍정적으로 검수했으므로 후속 정보 정리에서는 본문 열·지도 크기·탐색·선택 동작을 유지한다. 시간 요약은 소요 시간/미확인 상태를 주 값으로, 확인된 방문·구간 수와 직접 입력 여부를 보조 글자로 분리한다. 체류와 다음 이동의 글자 강조를 구분하고, 선택 장소 상세는 위치 → 메뉴·요금·운영 → 연락·편의 정보 순으로 묶는다. 요금 펼침은 요금 행 가까이 두고 빈 정보 묶음이나 새 카드·탭을 만들지 않는다.

지도 아래의 선택 상세는 실제 장소 사진과 분류·주소를 먼저 보여주고 방문/체류·요금, 운영·연락 정보를 묶어 읽는다. 사진이 없거나 실패하면 사진 영역을 접으며 다른 장소 이미지나 빈 상자를 넣지 않는다. 충분한 상세 너비에서는 관련 정보를 두 열로, 좁은 영역은 한 열로 배치한다. 값은 16px/1.6, 이름은 14px이며 상세 본문은 내용에 맞춘 자연 높이와 최대 460px를 사용한다. 긴 원문만 내부에서 스크롤하고 적은 정보에 빈 높이를 강제하지 않는다. 높아진 지도/상세 묶음은 충분히 높은 화면에서만 고정한다. 상단 `일정 점검`과 예상 비용 옆 `!`는 본문을 미는 펼침 대신 마우스 올림/키보드 초점/터치로 작은 팝오버를 연다.

밝은 흰색·아이보리 바탕, Pretendard, 팀 연두색 포인트와 여행 준비의 공통 헤더·좌측 탐색·실행 버튼을 유지한다. 종합 본문만 최대 1440px이며 공통 준비 화면은 1152px로 유지한다. 제목·기간·저장 상태·오른쪽 `일정 수정`을 간결하게 묶는다. 장식 점·사진 격자·중복 코스/지도 제목과 큰 안내 띠를 추가하지 않는다.

첫 진입은 `전체 일정`이다. 모든 날짜의 확정 코스를 날짜별로 묶은 왼쪽 목록과 큰 지도를 함께 표시한다. 날짜 버튼은 목록과 지도를 같은 범위로 좁힌다. 전체 범위의 방문 번호는 날짜를 넘어 연속되며 지도 핀과 목록이 같은 node ID·순서·번호를 쓴다. 실제 캔버스 연결이 방문 순서의 기준이고 분리된 코스는 따로 표시한다. 독립 후보·댓글은 코스에 넣지 않고 날짜별 참고 내용으로 구분한다. 같은 장소를 여러 번 방문하면 각 방문을 유지한다.

상단 요약은 표시 중인 범위의 일정 점검, 체류/이동 시간의 확인 범위와 명시된 요금의 예상 합계를 표시한다. 누락된 시간은 0으로 취급하지 않고 `확인된 이동 N분 / N개 중 M구간 확인`처럼 부분 합계임을 드러낸다. 직접 입력 시간은 API 조회 시간과 구분한다. 유효한 현재 구간·조건 버전·이동수단에 맞는 조회 결과만 합산한다. 체류와 이동 합계를 하루의 실제 시작~종료 소요 시간으로 표시하지 않는다.

비용은 사용자 후속 요청에 따라 `priceLabel`·`feeText`의 전체 문장이 엄격한 원화·단위 문법과 맞을 때만 합산한다. 명시적 1인 금액은 저장된 예정 인원을 곱하고, 명시적 전체 금액(`전체 1회` 포함)은 방문당 한 번, 무조건 무료는 0원으로 센다. 명시적 범위는 하한·상한을 별도 합산하고 `약`의 의미와 원문을 보존한다. `1회`만 있는 가격은 인원 기준이 없으므로 전체 금액으로 가정하지 않는다. 메뉴·소개문 속 숫자, 조건부 무료, 상충하는 안내, 단위 없는 금액과 객실/박수 불명의 숙박비는 추정해서 채우지 않는다. 합산 불가 항목은 0원으로 만들지 않고 확인된 방문 수와 제외 이유를 드러낸다. 합계는 장소비 기준이며 교통/추가 지출은 별도다. 공식 홈페이지는 기존 안전한 HTTP(S) 주소만 사용하고, 외부 요금/위치 검색은 고정 HTTPS 검색 제공자에 공개 장소명·도시·주소만 인코딩한다. 방 이름·초대 코드·여행방 ID·개인 취향은 검색에 포함하지 않고 자동으로 검색하거나 결과를 확인했다고 주장하지 않는다. 생성 원본의 비용·검사·예상 시각을 편집본의 재계산 결과로 표시하지 않는다. 방문 시각은 `예상`으로 구분하며 캔버스 수정 뒤 자동 재계산하지 않는 한계는 문서에 기록한다.

`일정 점검`은 현재 표시 범위의 장소 위치·분리된 코스·이동 시간·장소 정보 조회 실패만 다룬다. 사용자 후속 요청에 따라 팝오버는 `needs-review`/`loading` 방문만 `상태 아이콘 | 장소명`과 작은 일차·분류·이유로 나열하고 완료 방문은 숨긴다. 의도적인 별도 코스는 기존 요약·목록 구분에서 안내하며 오류로 만들지 않는다. 예시는 실제 검수 행 대신 예시 안내를 보여주고, 실제 미완료가 없을 때와 방문 자체가 없을 때를 구분한다. 주 값은 `확인 필요 N건`/`확인 중 N건`이며 모든 요약 주 값을 같은 최소 44px 영역에 정렬한다. 점검의 강조선은 버튼 하단 전체가 아닌 글자 바로 아래에 맞춘다. 카운트 계산 기준은 변경하지 않는다. 유효한 직접 입력 시간과 현재 조건/이동수단/양 끝 장소가 일치하는 검증 시간은 완료로 본다. geometry 없음은 시간 오류가 아니다. 후보·댓글·날짜 간 연결은 검사에 섞지 않고 추가 코스를 임의로 연결하지 않는다. 점검과 비용 팝오버는 한 번에 하나만 열고 trigger와 내부 사이를 마우스로 이동할 수 있으며, 키보드·터치로도 조작한다. Escape·바깥 선택·범위 변경 때 닫고, 명시적 방문 선택에만 스크롤·키보드 초점을 옮긴다. 일정 자동 수정이나 영업시간·시간 충돌·예산 검증 완료로 표현하지 않는다.

`예상 비용`은 금액/범위와 `원`만 표시하며 계산할 수 없거나 방문이 없으면 `—`로 표시한다. `확인된 비용`·`약`·인원 캡션은 주 값에 붙이지 않는다. 바로 뒤 `!` 버튼을 팝오버의 위치·초점 복귀 기준으로 사용하고 제외 항목 수와 부분 합계/예시 의미를 접근성 이름으로 제공한다. 비용 팝오버는 왼쪽 `예외 항목`, 오른쪽 `닫기`를 같은 헤더 줄에 두며 인원/합산 범위 등의 시각 안내 문단은 제거한다. 저장 인원·합산 범위·근사치 여부·교통/추가 지출 제외 의미는 접근성 이름에서 유지한다. 합산하지 못한 방문만 장소명과 검색 동작을 같은 상단 기준선에, 일차·간결한 사유를 그 아래에 보여 준다. `합산 결과`와 `합산 제외`의 중복 행은 만들지 않고 제공된 원문·공식 링크는 아래에서 보존한다. 정상 무료·정상 합산 방문은 나열하지 않으며 실제 0원과 계산 불가를 구분한다. 금액 계산 규칙 자체는 바꾸지 않는다.

날짜 탐색 오른쪽의 `일정 정보` 버튼과 펼쳐지는 세 줄 가이드는 사용자 요청으로 제거했다. 날짜/전체 일정 선택과 상세 요금/소개 펼침은 유지한다. 기존 예상 방문 시각이 캔버스 수정 뒤 자동 재계산되지 않는 동작 한계는 문서에 기록하며, 제거된 가이드가 화면에 있다고 설명하지 않는다.

방문 행은 번호·예상 시각·장소명·머무는 시간·짧은 요금을 읽고, 바로 아래에서 다음 장소와 이동수단·시간을 확인한다. 실제 사진이 있으면 작은 썸네일만 표시하고 사진 없음/실패에는 빈 사진 상자를 만들지 않는다. 상세가 열려도 다음 방문은 밀리지 않는다. 목록은 문서 흐름을 유지하고, 선택 상세는 지도 아래 한 개의 독립된 영역에서 교체한다. 데스크톱 상세 본문만 높이를 제한해 긴 소개·요금의 펼침이 지도·방문 행을 밀지 않도록 한다. 제목에는 선택 날짜·방문 번호·장소명을 함께 표시한다.

선택 상세는 제공된 이미지·위치·메뉴·운영·휴무·연락처·예약·주차·안전한 HTTP(S) 홈페이지를 읽는다. 짧은 요금은 첫 비어 있지 않은 `priceLabel`, 없으면 `feeText`를 사용한다. 한 줄·28 Unicode 문자 이하일 때 원문을 표시하고 그 외에는 `상세 요금 있음`으로 표시한다. 길거나 서로 다른 두 요금은 이름 있는 요금 펼침으로 전체를 제공하고 소개와 독립적으로 조작한다. 다른 방문을 고르면 펼침을 초기화한다. 버튼은 44px 이상, 즉시 보이는 키보드 초점과 고유한 펼침 영역 ID를 갖는다.

지도의 실제 SDK·검증 geometry와 기존 `선택 장소 위치 / 전체 경로 보기` 동작을 재사용한다. 같은 방문 행을 다시 눌러도 해당 지도 위치로 이동한다. 현재 검증된 도로 좌표만 지도 선으로 표시하고 좌표 누락·조회 실패에는 직선이나 임의 핀으로 대체하지 않는다. 경로 결과만 갱신될 때 지도 인스턴스·중심·확대는 유지한다. 실제 경로 문제의 재시도는 지도 옆 한 곳에 모으고 매 구간에 긴 오류를 반복하지 않는다. 지도 핀 선택은 페이지나 초점을 강제로 옮기지 않는다.

PC는 왼쪽 360~384px 일정과 나머지 지도 폭의 두 열이며 900~1099px는 320px 목록을 사용한다. 충분히 높은 화면에서만 지도/상세 묶음을 고정하고 낮은 높이에서는 해제한다. 휴대폰은 지도·독립 상세·날짜별 일정 순서로 배치한다. `장소 상세 보기 / 지도 보기 / 일정 목록 보기`로 해당 영역의 스크롤과 초점을 함께 옮기며 상세를 각 방문 사이에 다시 넣지 않는다. 날짜가 길 때는 날짜 탐색 안에서만 가로로 스크롤한다.

캔버스 `결과 종합`은 패널 토글 바로 왼쪽에서 같은 방의 종합 화면으로 이동한다. 두 탐색 버튼은 같은 높이·테두리·반경·선 아이콘의 `tw-canvas-header-action`을 공유한다. 공통 탐색·준비 입력·캔버스 저장·경로 생성 알고리즘·BE·AI·DB는 이 화면 재구성에서 변경하지 않는다. 기술 검사 통과와 사용자 디자인 승인을 구분한다. 사용자 요청에 따라 서버·브라우저를 실행하지 않고, 실제 화면은 사용자가 BE `run.py`로 검수한다.

## 첫 시작 화면

현재 로컬 `design/wayfind-ui-review`에서는 기존 동작을 유지하며 시작·여행 준비·개인 취향을 Wayfind 방향으로 재디자인해 검수 중이다. 아래 기존 화면의 기능 범위는 유지하며, 새 시각 기준과 실제 확인 결과는 [Wayfind UI 검수](wayfind-ui-review.md)에 기록한다.

## 여행방 워크스페이스 후속 변경

기본조건 변경 안내는 [변경 안내·진입 화면 정렬](preparation-condition-notice.md)을 따른다. 개인 데이터 자동 재조회와 별개로 최신 조건 변경 안내를 유지하고, 해당 조건의 준비 완료 성공 후 해제한다. 지역 카드 체크 아이콘은 제거하되 실제 선택과 접근성 상태는 유지한다.

버튼의 최신 기준은 [여행 준비 버튼 통일](preparation-action-system.md)이다. 주요 실행 버튼은 투명 바탕·얇은 밑선·정사각 화살표 영역의 같은 컴포넌트를 사용한다. 이동수단은 원 표시가 없는 단일 선택 버튼이다. 지역 복수 선택은 BE 규격을 논의할 후속 범위다.

최신 기준은 [여행 준비 상태와 최종 로컬 검수](preparation-confirmation-review.md)다. `내 취향` 이름, 참여자 공개 상태, 명시적 준비 완료와 이동수단 라디오를 적용한다. 최종 참여자·이동수단 재배치는 사용자가 `run.py`로 검수하며 에이전트가 서버·브라우저를 실행하지 않는다.

2026-11-10 여행 준비 후속 기준은 [여행 준비 입력 정리](preparation-ui-refinement.md)를 우선한다. 왼쪽 아이콘 탐색은 중앙을 밀지 않는 오버레이이며 상단에는 참여자와 준비 상태를 둔다. `여행 기본조건`은 첫 `충북 전체` 카드와 11개 시군 사진 카드로 지역을 선택한다. 현재 선택값을 누르면 목록을 열고 닫으며 별도 드롭다운은 두지 않는다. 두 입력 영역 제목은 배경 없이 기준선과 구분선을 맞추고 조건 저장은 입력 아래 오른쪽에 둔다. 숙박·고정 일정은 기존 저장값을 보존한다. `정보 입력`의 분석 상태는 입력창 안에서 표시하며 첫 최종 저장 후 정리한 취향을 보여 준다. 이후 원문 수정·저장·재분석에도 취향 편집 영역을 유지하고 최신 분석 여부를 별도로 표현한다. 피할 조건·식사 조건의 필수 여부는 설명형 체크 항목으로 편집한다. 분석·저장 버튼은 오른쪽으로 정렬하고 상단 헤더의 방 이름 중복 표시는 제거한다.

여행방은 공통 조건과 내 취향을 중앙의 큰 입력 영역에 함께 배치한다. 입력을 사이드바 안에만 두지 않는다. 얇은 헤더·구분선과 밝은 표면, 제한된 연두 강조를 사용하며 좌측 탐색과 우측 장소 패널은 열고 닫을 수 있다. 휴대폰은 패널을 닫은 상태로 시작한다.

일반 방의 개인 입력은 기존 BE의 본인 조회/저장/해석 API에 연결됐다. 원문 저장 → 실제 AI 제안 → 해석값 저장이 모두 성공한 뒤에만 분석·저장 완료로 표시한다. 직접 검토 확정은 별도 서버 정책이며 분석이 임의로 확정하지 않는다. 개인 원문을 브라우저 영구 저장소나 공통 응답에 보관하지 않는다.

일정 캔버스는 이 기기의 예시 편집 화면으로 구분한다. 자유 배치, 연결·해제, 우클릭/버튼 메뉴, 교체·날짜 이동과 실행 취소/다시 실행을 제공한다. 연결선이 순서의 기준이며 대체 후보와 연결이 필요한 기존 동선을 구분한다. 장소·날짜·연결을 바꿔도 남은 카드를 자동으로 잇지 않는다. 실제 연결 범위·실행 주소·검증 결과는 [워크스페이스 검수](workspace-ui-review.md)를 따른다. 아래 초기 화면의 메모리 초안 설명보다 이 후속 변경을 우선한다.

기본 경로는 사용자가 검수한 `충북 여행 계획` 시작 화면이다. 밝은 배경·관광지 사진 슬라이드·만들기/참여 탭·오른쪽 생성 버튼 배치를 보존하고 하단 푸터만 제거했다. 이 화면은 `public/assets/live-entry`의 자체 CSS 토큰과 HTML/JavaScript를 사용한다. 기존 React 공통 컴포넌트·테마는 `?preview=ui`에서 유지하며 이번 변경에서 재설계하지 않는다.

생성·코드 참여는 실제 BE 기기 세션·멱등 API를 호출하고 성공 후 `/room.html?tripId=...`로 이동한다. 방 진입 뒤에는 기존 본인을 재접속해 실제 방 정보를 표시하고, 여행 준비·내 취향 및 제약의 두 화면을 제공한다. 사용자 와이어프레임의 정보 구조에 시작 화면의 밝은 배경·짙은 큰 제목·연두 포인트를 적용한다. 일반 모드의 공통 조건과 전체 참여자 준비 상태는 서버 데이터다. OWNER만 공통 조건을 저장하고 버전 충돌 시 편집 입력을 보존한다. 개인 입력과 본인 직접 확정은 준비 API에 연결되며, AI 해석 제안은 자동 저장·확정하지 않는다. 별도 개인 정규화 검토 후 일정 생성 화면에서 진행 상태·일정·지도를 확인한다. 개인 원문은 개인 화면에만 표시하고 공통 조건 버전이 바뀌면 개인 초안은 보존하면서 현재 공통·개인 버전으로 다시 확인해야 한다. 사용자가 바꾼 항목별 미정 안내·예산 안내와 옅은 표시를 유지한다. 상세 연동·검수 방법은 [공통 조건·준비 상태](shared-preparation.md)와 [여행방 준비 화면](room-dashboard.md), 사진 원본과 실행 방법은 [여행방 시작 안내](trip-entry.md)에 기록한다.
