# 공동 일정 캔버스

상태: 공동 초안 FE/BE 로컬 구현 및 오프라인 검증 완료, 사용자 실행 검수 대기. 전체 일정 생성 기능의 완료를 뜻하지 않는다.

후속: 준비에서 실제 생성한 코스를 같은 공동 캔버스로 가져오는 흐름을 연결했다. 새 기본 진입은 [여행 준비에서 공동 캔버스까지](preparation-schedule-design.md)를 우선한다. [이전 병합 기록](canvas-generation-integration.md)은 연결 전 상태의 기록이다.

## 범위와 데이터

ACTIVE 여행방 참여자는 장소 카드, 날짜, 연결선, 색, 배치와 댓글을 함께 편집한다. 이는 생성·저장된 일정과 별개인 검토 초안이다. 캔버스는 일정 확정, 경로 검증, 공통 여행 조건 편집 권한을 제공하지 않는다. 개인 취향 원문과 추천 프롬프트는 캔버스 문서에 넣지 않는다. 댓글은 사용자가 작성해 공유하는 내용이다.

기존 공유 문서는 `schemaVersion: 3`으로 계속 읽을 수 있다. 날짜 박스를 옮기거나 날짜 연결을 편집하면 버전 4로 저장한다. 장소 카드가 참조하는 DB 키는 두 버전 모두 `contentid`이다.

## 날짜별 캔버스

날짜 제목을 드래그하면 소속 카드가 함께 움직인다. 날짜 박스의 연결점을 이어 원하는 다음 날짜를 표시하고, 선을 선택해 삭제할 수 있다. 기본 배치에서는 날짜 순서대로 연결한다. 연결을 모두 삭제한 방에서는 빈 목록도 그대로 저장한다. 박스 색상은 날짜 ID로 정해 같은 방의 참여자가 같은 색을 본다. 생성된 세 장소의 기본 배치는 위 두 곳과 아래 가운데 한 곳이다.

버전 4의 `days[].position`은 캔버스 위 박스의 위치이며 생략된 박스는 자동 배치한다. `dayLinks`는 날짜 ID 사이의 방향 연결 목록이다. 카드 위치는 날짜 내부 좌표로 저장한다. 날짜 연결은 이동시간을 조회하는 장소 연결(`edges`)과 독립적이다.

장소 상세 응답의 `imageUrl`은 새 클라이언트가 `X-Canvas-Version: 4`를 보낼 때 제공하며, `feeText`에 DB의 요금 설명이 들어 있다. 사진이나 가격이 없는 장소도 열 수 있다. 요금 설명이 비어 있는 장소는 근거가 있는 경우에만 `priceLabel`에 1인·1박 등 적용 기준과 금액을 제공한다. AI 추천과 직접 검색 결과는 개인 패널에 표시하고, 사용자가 후보를 선택해야 공유 캔버스에 추가하거나 기존 장소를 바꾼다.

구간을 선택하면 여행 준비의 공통 이동수단을 확인하고 이 브라우저에서 사용할 이동수단과 소요 시간을 지정할 수 있다. 직접 입력한 값은 방·연결선·양쪽 장소에 묶어 브라우저에 보관한다. 다른 이동수단으로 바꾼 경우 직접 입력하기 전까지 그 구간의 시간을 미정으로 표시한다. 공통 설정으로 복원하면 기존 경로 조회 결과가 다시 표시된다.

## API

| Method | Path | FE 동작 |
| --- | --- | --- |
| GET | `/api/v1/trips/{tripId}/canvas` | 현재 revision과 공유 문서를 읽는다. |
| PUT | `/api/v1/trips/{tripId}/canvas` | `{expectedRevision, document}`를 UUID `Idempotency-Key`와 함께 저장한다. |
| GET | `/api/v1/trips/{tripId}/canvas/places/{contentid}` | 참조 장소의 허용된 DB 상세 정보를 읽는다. |
| GET | `/api/v1/trips/{tripId}/generation/places?q=&limit=20` | 기존 장소 검색을 재사용한다. |
| POST | `/api/v1/trips/{tripId}/canvas/recommendations` | 프롬프트·날짜·제외 장소를 보내 한 장소와 검토 대안을 받는다. |
| GET | `/api/v1/trips/{tripId}/canvas/route?sourceContentid=&targetContentid=&expectedConditionsVersion=` | 저장된 이동수단과 DB 좌표에 따른 구간 이동 시간을 받는다. |

공동 캔버스는 31일, 노드 500개, 연결 500개, JSON 1MiB 제한을 적용한다. 장소는 같은 날짜의 장소끼리만 앞뒤 하나씩 연결할 수 있고 순환은 거부한다. 댓글에는 연결점을 만들지 않는다. 장소 삭제/날짜 이동 시 이어진 연결을 함께 제거하며 다른 장소를 자동으로 잇지 않는다.

최신 revision이 바뀌어 PUT이 `VERSION_CONFLICT`를 반환하면 FE는 최신 문서를 읽어 ID·필드별 3-way merge를 시도한다. disjoint 변경을 합친 문서는 새 revision 및 새 멱등성 키로 저장한다. 겹침·삭제/수정 충돌·유효하지 않은 연결은 자동 저장을 멈추고 해결 선택을 보여 준다. 네트워크 결과가 불명확한 저장은 같은 body·revision·key로만 재시도한다. 추천 목록에서 선택한 장소를 반영하며, 저장 재시도 때 추천 API를 다시 호출하지 않는다.

화면은 1초 간격의 가시 탭 동기화와 포커스 복귀 조회를 사용한다. 숨겨진 탭은 주기 조회를 멈춘다. 실행 취소·다시 실행은 서버에 반영된 본인 변경에 한정하고 현재 문서에 역변경을 합쳐 다른 참여자의 disjoint 변경을 보존한다. 같은 필드 변경이나 새 의존 연결이 안전성을 깨면 실행을 막는다.

## 검증 기록

단위 테스트와 type/lint/build는 FE 로컬에서 확인한다. 실제 여행방 API, 공용 DB 및 두 브라우저의 동시 편집은 사용자가 실행해 확인해야 하며, 미실행을 통합 성공으로 표시하지 않는다.

2026-11-11 최종 검사: `npm run check`의 타입 검사·lint·프로덕션 빌드 통과, `npm test` 87개 통과. lint는 기존 `usePersonalPreparation.ts:101`의 ref 경고 1건만 남았다. 정적 디자인 검사 4개 파일에서 fail/reflex/warn 0건이며 화면 렌더 검수는 하지 않았다. Sol high 독립 검토에서 발견한 날짜 전환·연결 제거 후 불필요한 대기 경로 조회는 취소 및 회귀 검사로 해결했다. 기존 공동 초안의 CAS/충돌·본인 실행 취소·개인정보 경계 검토도 완료했다.

현재 PC의 BE는 `chungbuk_trip1`에 migration 004의 두 지원 테이블을 적용했다. 서버를 이미 실행했다면 파이참에서 사용자가 중지 후 `run.py`를 재실행하고 브라우저를 새로고침한다. FE 빌드는 준비되어 있다. 실제 Gemini·Kakao 호출과 두 브라우저의 동시 편집은 아직 검수하지 않았다. 최초 검사에서는 카카오 REST 키가 없었으며, 사용자 추가 후 `KAKAO_REST_API_KEY` 설정의 존재를 확인했다. 키 설정만으로 실제 지원 이동수단·제공자 응답을 검증한 것은 아니다.

## 편집 도구와 보존

상단 도구는 명령 등록부로 확장하며 실행 취소·다시 실행·댓글·화면 맞춤·장소 패널 열기/닫기를 제공한다. 날짜 이동·선택·추가를 한 묶음으로 배치한다. 노드와 빈 공간의 우클릭 메뉴는 키보드 메뉴 키 또는 Shift+F10으로도 열 수 있다. 복사·붙여넣기·제거·연결 해제·날짜 이동·색상 변경은 선택 대상에 따라 활성화한다.

노드 선택 시 오른쪽은 DB 장소 정보 또는 공유 댓글 편집으로 바뀐다. 선택을 해제하면 AI 추천·대안·직접 검색을 보여 준다. 추천 결과는 선택 전까지 공유 문서를 바꾸지 않는다. 결과가 불명확한 추천은 같은 요청으로만 확인하며 새 추천은 사용자가 별도로 시작한다.

댓글은 입력 중 빈 내용을 허용하고 저장 또는 Ctrl+Enter로 공유한다. 다른 사람이 같은 댓글을 바꾸면 입력 버퍼를 보존하고 최신 내용과 내 내용의 선택을 받는다. 준비 화면으로 이동했다 돌아와도 저장 대기 요청·본인 실행 취소 기록·댓글 입력은 현재 앱 메모리에 보존한다. 브라우저 종료·새로고침 후 미저장 입력 복원은 제공하지 않는다.

## 연결선의 이동 시간

연결선에는 이동수단과 분/시간을 표시한다. 조회 중·미확인을 구분하며 모르는 값을 0분으로 대체하지 않는다. 장소쌍의 방향과 저장된 조건 버전이 달라지면 기존 값을 버리고 조회한다. 위치 드래그·댓글 변경·공유 문서의 주기 조회는 같은 구간을 다시 호출하지 않는다. 조회 동시 실행은 두 개로 제한한다. 시간 표시는 방문순서·영업시간·전체 예산을 확정하거나 검증하는 기능과 별개다.
