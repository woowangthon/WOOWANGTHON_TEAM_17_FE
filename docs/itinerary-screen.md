# 여행 일정 화면

사용자가 제공한 일정 시안의 정보 구조를 기존 연두색 테마로 적용한다. 여행방 헤더·사이드바와 다른 탭은 유지한다. 이번 요청은 로컬 수정·확인으로 한정하며 커밋·push·PR·Notion 변경은 수행하지 않는다.

## 표시 범위

병합 후 일정 화면은 전용 셸에서 기존 상단 여행방 정보·참여자 사이드바·올리브 포인트·둥근 컨트롤을 유지한다. 친구의 준비·취향·캔버스 테마는 별도로 유지한다. 준비 화면에서 각자가 저장·직접 확정한 개인 조건을 본인이 검토하고, 방장의 ‘일정 만들기’는 최신 `GET /generation`의 준비 상태·입력 토큰·설정 버전을 확인한 뒤 기존 생성 작업 API를 호출한다. 완료된 실제 일정만 `view=generation`의 목록·지도·상세에 표시한다. 일정이 없는 방에 예시 코스·빈 지도 결과를 주입하지 않는다. 생성 준비가 부족하면 공개 사유와 개인 검토·생성 설정 진입을 안내한다.

- 상단: 여행명, 기간·인원·이동수단, 초안/저장/오래된 상태, 비용과 검사 결과.
- 본문: 날짜별 코스 선택, 지도 또는 코스 순서 도식, 선택한 장소의 시간·체류 시간·비용·영업정보.
- 목록·상세·마커·경로에는 해당 날짜의 `PLACE`만 사용한다. `START`·`END`는 공동 코스에서 숨긴다. 날짜 변경이나 결과 갱신 시 현재 날짜에 속하는 장소로 선택을 보정한다.
- 조건 검토·생성 설정은 접을 수 있는 영역으로 분리한다. 출발 위치 입력은 이번 일정 화면에서 제거한다.

## 실제 정보와 미제공 정보

기존 일정 생성·조회·저장 API, 권한, 버전 충돌과 재확인 동작을 유지한다. 출발 기준점과 서버 DTO는 삭제하거나 임의 값으로 채우지 않는다. 출발 기준점이 없는 일정의 생성 가능 여부는 기존 서버 조건을 따르며, 프로젝트 전체에서 시작 위치를 제거하는 작업은 후속 범위다.

지도 서비스는 유효한 장소 좌표와 검증된 경로만 표시한다. 지도 키 누락이나 로딩 실패 시 번호를 누를 수 있는 코스 순서 도식을 보여주고 실제 이동 경로가 아님을 명시한다. 지도와 도식의 선택은 같은 장소 상세를 표시한다.

사진·추천 이유·이동 소요 시간·변경 이력·장소 추가/교체는 현재 응답이나 API가 제공하지 않는다. 이를 임의로 채우거나 동작하는 것처럼 표시하지 않는다. 검사 내역은 서버가 반환한 검증 결과를 표시한다. 전체 비용이 미확정이면 확인된 일부 금액으로 전체 합계나 예산 여유를 단정하지 않는다. 개인 원문·해석 근거는 공동 코스 화면에 표시하지 않는다.

## 로컬 미리보기

`.agent-work/vite-itinerary-demo.config.ts`는 Git에서 제외된 검수용 설정이다. 실제 `RoomPage`와 일정 컴포넌트에 2일 예시 응답을 제공하며 외부 BE/DB로 요청을 전달하지 않는다. 예시 응답에는 `START`·`END`가 남아 있어 화면에서 제외되는지 확인할 수 있다. 시안과 같은 저장 상태·금액도 예시이며 실제 생성·저장 검증을 뜻하지 않는다.

검증은 `npm test`, `npm run check`, 데스크톱·모바일의 날짜/장소 선택, 검사창의 키보드·Escape·초점 복귀, 시작 위치 미표시를 포함한다. 실제 실행 결과와 캡처는 완료 보고에서 별도로 구분한다.

## 이번 로컬 변경 검증

### 준비 화면 생성 연결·셸 복원 (2026-11-11)

- 친구 준비 화면의 실제 저장·준비 완료 뒤 본인 생성 조건을 검토하고 방장의 하단 버튼으로 최신 준비 상태 조회 → 생성 작업 요청 → 진행 조회 → 실제 코스 목록·지도·상세로 이어진다. 미저장 입력·처리 중·버전 변경·권한 상실은 차단하며 참여자 검토를 대신 완료하지 않는다.
- 생성 API에 도달하기 전 입력 변경을 재확인하고, 응답을 기다리는 동안 수정한 초안을 화면 이동으로 잃지 않게 한다. 불명확한 실패는 동일 멱등 키로 재시도하고 진행 작업은 중복 생성하지 않는다. 완료된 기존 일정은 별도 보기 동작으로 연다.
- 개인 해석 검토는 저장 응답이 부분 검토여도 성공(HTTP 200)일 수 있으므로, 생성 기준을 충족하기 전에는 누락 필드를 알려주고 저장 완료로 오인시키지 않는다. 저장된 적용 범위와 의미 확인 상태는 새로고침 뒤에도 복원한다.

### 2026-11-11 부분 검토 저장 안내 수정

- 실제 사용자 방을 읽기 전용으로 확인했다. 예정 인원과 참여 인원은 모두 1명으로 일치했지만, 좋아하는 항목만 검토되고 피하고 싶은 항목이 미해석 상태여서 서버 내부 검토 준비 판정이 false였다. 1인 여행은 차단 원인이 아니다.
- 필드별 태그 선택·전체 의미 확인을 저장 전에 검사하고, 태그가 없는 항목과 부분 저장 상태를 구체적으로 안내한다. 저장한 범위·체크를 복원하고 검토 저장·재해석 뒤 공개 생성 상태를 다시 조회한다. 기존 API와 생성 차단 기준은 유지한다.
- 실제 BE 검증 함수로 미해석 필드가 남으면 차단되고 지원되는 항목을 직접 검토하면 통과하는 것을 재현했다. 사용자 입력·정규화·DB는 변경하지 않았으며, 해당 방의 미해석 조건과 생성 차단 자체를 해결한 검증은 아니다.
- 전체 테스트 79개와 typecheck·lint·build 통과(lint 기존 경고 8개). 별도 Sol planner·Luna worker·Sol 독립 검토를 진행했고 P1/P2 지적은 없다. 이번 변경의 브라우저·모바일·키보드 실제 동작 검수는 미실행이며, 사용자의 run.py 검수 흐름을 유지하고 새 서버·브라우저를 실행하지 않았다.

## 실제 Kakao 지도 추가 확인

후속 요청에서 예시 서버가 지도 키를 빈 문자열로 덮어쓰던 설정을 제거했다. `.env.local`의 기존 JavaScript 키를 그대로 사용하며 키 값은 문서·로그·커밋에 남기지 않는다. SDK 응답은 `http://localhost:5176`에서 도메인 불일치 401, 등록된 `http://127.0.0.1:5173`에서 200이었다. 비어 있던 5173 포트로 예시 서버를 옮겨 카카오 개발자 설정 변경 없이 검증했다. 예시 응답은 여전히 BE/DB에 연결하지 않는다.

실제 SDK의 지도 타일·번호 마커, 마커 클릭과 목록·상세 동기화, 날짜별 마커 4개/3개 전환을 확인했다. 날짜 전환 시 이전 지도 DOM을 제거해 지도 요소가 쌓이지 않게 보완했고, 전환 후 지도 컨테이너의 직계 자식 수가 3개로 유지됨을 확인했다. `npm run check`도 다시 통과했다(lint 경고 9개 유지).

검증된 도로 경로가 없는 경우 임의 이동선을 그리지 않는다. 실제 경로 응답이 있는 `verified` 구간만 선으로 표시한다. 등록 도메인에서 SDK를 사용해야 한다는 기준은 [Kakao 공식 가이드](https://apis.map.kakao.com/web/guide/)를 따른다.

## 실제 자동차 경로 예시

경로 조회 가능 여부를 묻는 후속 요청에서 기존 BE `KakaoRouter`와 BE에 설정된 REST 키로 카카오모빌리티 자동차 길찾기를 호출했다. 예시 장소 사이 5개 구간 모두 `verified`이며 도로 좌표 312개를 받았다. 예를 들어 도담삼봉→구경시장은 4,011m/486초, 구경시장→카페는 604m/156초였다. 거리·시간은 조회 시점 응답이며 미래 여행일의 도착을 보장하지 않는다.

반환된 공개 경로 데이터만 Git에서 제외된 `.agent-work/kakao-course-routes.json`에 보관하고 예시 일정의 edges에 연결했다. REST 키는 BE 밖으로 복사하지 않았다. 브라우저에서 1일차 도로 선 3개·마커 4개, 2일차 도로 선 2개·마커 3개를 확인했다. 이 예시는 조회 결과를 보관한 것이며 장소 변경 시 자동 재조회하는 새 기능이나 실제 여행방 생성·DB 저장 검증은 아니다. 이동 거리·소요 시간 데이터는 받았지만 코스 사이 안내 문구에 표시하는 기능은 이번 예시 연결에 포함하지 않는다.

API 출처: [Kakao Mobility 자동차 길찾기](https://developers.kakaomobility.com/guide/navi-api/directions). 기존 앱 소스·API 계약 변경 없이 예시 응답만 추가했으며 커밋·push는 하지 않았다.
